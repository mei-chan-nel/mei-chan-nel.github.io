# Interactive Lab

情報Ⅰの概念を操作・実験・可視化で理解する教材の入口です。共通の入口と、個別の実験教材を管理します。

学習アプリと同じ6分野で整理します。

1. 社会・セキュリティ
2. デジタル表現
3. ネットワーク
4. データ活用・DB
5. アルゴリズム
6. 情報デザイン

動画解説ページと同じく、カテゴリの見出しの下に個別教材のカード一覧を置く構成です。完成した教材をカテゴリに登録し、一つずつ体験を設計・実装します。個別教材のURLは `/lab/<slug>/` に統一する方針を維持します。

## 構成

- `catalog.mjs`: 6分野の名称と説明、完成した教材の一覧。
- `tools/build-pages.mjs`: 入口 `index.html` の生成。個別ページは生成しません。
- `lab.css`: 入口のレイアウト。既存 `assets/site.css` の配色・ヘッダー・フッターを使用します。
- `navigation.mjs`: ナビゲーションの表示補助。解析・広告スクリプトは読み込みません。

```sh
node lab/tools/build-pages.mjs
node lab/tools/build-pages.mjs --check
python3 scripts/preview_site.py --host 127.0.0.1 --port 8773 --app-root /workspace/info1-quiz-app
```

配信した `/lab/` を開いて確認します。Labの表示にnpmインストールは不要です。

## 暗号通信シミュレーター

`/lab/crypto-communication/`。通信経路の中継機を操作するCharlieとして、鍵・認証・署名の役割を学ぶレトロゲーム風の実験です。通過するデータを自動で記録し、ナレーション・行動・正誤・結果を一つのパネルに表示します。

1. 共通鍵：平文で配送された共通鍵で盗聴し、本文を書き換えて再暗号化する。
2. 公開鍵：Bobの公開鍵をCharlieの鍵にすり替えて共通鍵を入手し、本物のBobの公開鍵で包み直す。
3. 認証局CA：事前登録されたCA公開鍵で証明書の署名と相手名を確認し、Bobの公開鍵のすり替えを拒否する。Aliceの共通鍵と本文はCharlieに読めなくなる。ただし、Bobが送信者を確認しないため、Charlieが新しく用意した共通鍵と偽の本文の両方への差し替えは受理される。
4. 電子署名：BobもCAでAliceの公開鍵を確認し、本文の署名を検証する。Charlieが自分の共通鍵と本文を送り込み、Charlieの秘密鍵で署名しても、Aliceの署名としては検証を通らない。

- `model.mjs`：数学を抽象化した不透明な暗号文・署名・証明書。秘密のペイロードは内部に保持する。Aliceの共通鍵とCharlieが生成した共通鍵は別で、Charlieの鍵でAliceの暗号文を開けることはない。毎回の開始・再挑戦で鍵を更新する。
- `quest.mjs`：鍵の選択、正誤表示、誤答地点からの再挑戦、実際の通信による誤答の結果確認。「Bobへ転送する」など単独の行動もカードで明示する。
- `app.mjs` / `unified.css`：クリックで行動や鍵を即実行し、別の決定画面は出さない。正誤は緑・赤で示し、正解後の「次へ」はパネル内の共通位置に保つ。「一つ前へ」は会話・復号・転送・鍵の生成・ラウンド変更も巻き戻す。以前の鍵やAlice・Bob・CAの秘密鍵は候補に出さない。
- `storyboard.mjs`：Alice・Bob・Charlieを主語にした短いナレーション。Bobの鍵はBobからAliceへ流れる。CAへの申請・本人確認・発行・返却を表示し、Aliceの証明書はCharlieが行動するまでBobに登録されない。
- `characters.svg` / `packets.svg` / `authority.svg`：3人のドット絵、人物のすぐ上を流れる鍵・メッセージ・署名・証明書の図形。認証局は3人より上側の独立した段に配置する。電子署名は別添えで示す。
- `explanations.mjs`：全ての解説を最初から表示し、枠内でスクロールできる。CAで受信者の鍵を確認することと、受信者が送信者を確認することを区別する。
- `display.mjs` / `viewport.css` / `screen-layout.mjs`：PC・スマートフォンの全画面表示と端末ごとの配置。通常表示への切り替えでも実験を保持する。
- 元の本文は、その暗号文をCharlieが復号するまで非表示。Round3・4でCharlieが用意する偽の本文は、未解読のAliceの本文と分けて表示する。
- 公開鍵暗号は共通鍵の配送、共通鍵暗号は本文の暗号化、署名用秘密鍵は電子署名の作成、検証用公開鍵は署名の検証に使う。
- CAとの回線もCharlieが操作できるが、ブラウザに事前登録されたCA公開鍵や各人の秘密鍵は操作できない。本物のCharlie名義の証明書も、相手名が違うためBobの証明書として拒否する。
- 実際のTLS全体を再現する教材ではない。数学、ビット単位の攻撃、再送攻撃、証明書チェーン・期限・失効は省略する。署名だけで再送を防ぐとは説明しない。

```sh
node --test scripts/crypto-communication.test.mjs
node lab/tools/build-pages.mjs --check
```
