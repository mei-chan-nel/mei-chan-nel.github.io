# 問題マップ

情報デザインの教材。見出しは「情報の可視化、問題マップ」。公開パスは `/lab/question-map/`。Labの共通シェルで生成し、共通のナビゲーション・配色・広告枠を使用します。HTMLの本文は `../tools/templates/question-map.html`、登録は `../catalog.mjs` が正本です。

## データ

実行時に `/info1-quiz-app/data/questions/` の4ファイルを `no-cache` で取得します。問題・選択肢・解説・タグ・出典は `completed_questions.json` のオブジェクトを直接参照し、地図用の本文・コピー・加工した問題データは生成しません。

- `map_points.json`：`points[questionId] = [x, y]`。PCA(50) → t-SNEの既存座標を使用。
- `map_terms.json`：`terms[term] = [questionId, …]`。自動抽出の候補から表示する語を選択。
- `map_metadata.json`：schema version、問題数、生成元のSHA-256、配置方法を確認。

全ID・問題数・有限座標・3ファイル間の生成元ハッシュを検査します。Web Cryptoが使えるHTTPSまたはlocalhostでは本文のSHA-256も照合します。生成元のWindows環境とGit配信の改行差を考慮し、LF・CRLFの両方を照合します。Web CryptoのないHTTP環境では構造・ID・世代整合性の検査を使用します。欠落・不一致・通信失敗時は理由と再読み込みボタンを表示します。

現在の原本は1,438問・1,438点・1,312語候補。実際の件数はJSONから取得します。候補には文章の断片が含まれるため、長さ・文字種・語尾を保守的に絞ります。本文のタグは低倍率で優先表示し、中倍率で候補語を加えます。語の厳密な形態素解析や意味保証は行いません。

## 表示と操作

Canvasに座標点・地形・海岸線を描き、読み上げや選択のできるDOMラベルとカードを重ねます。4単位の空間索引で表示範囲を検索し、表示するDOM数を制限します。正答率の地形は履歴更新時だけ低解像度の場を計算して再利用します。

初期の全体表示を1倍とし、文字を表示せず地図だけを見せます。拡大率約1.5・3.1・6倍でタグ、単語、問題文へ進みます。選択肢と解説は問題文をクリックして開く詳細に表示します。境界の8%の幅で切替の振動を防ぎ、ラベルは黒字・白い縁取りの背景なし表示。表示中の文字は拡大で衝突判定から外さず、地理的アンカーを維持して大きくなりながら徐々に薄れます。移動で候補が外れた場合も650msで減衰し、引くと再表示します。表示範囲の地域ごとの出現数・特徴度から新しいラベルを選び、文字幅を測って空いた領域に置きます。

ヘッダーは「タグ・単語・問題・自動」の4ボタンです。初期はタグと自動が選択され、倍率に応じて主な選択がタグ→単語→問題へ移ります。全体表示ではこれまでどおり文字を省き、タグを自動表示の対象として選択します。タグ・単語・問題を押すと、その時点の選択を引き継いで該当項目を反転し、「自動」が「手動」に変わります。手動は複数選択・全項目オフが可能で、拡大縮小しても選択を保ちます。「手動」を押すとカメラを動かさず、その倍率での自動選択に戻ります。設定用の別の行やズーム用の段階ボタンは置きません。

手動で選択した情報は全体表示でも表示し、タグは14〜28px、単語は12〜22pxの範囲で緩やかに拡大します。手動のラベルは毎回、表示範囲全体の候補を画面の地域ごとに順番に選び直します。以前のラベルが表示枠を占有し続けないため、拡大してから引いた場合も他の地域に再配分できます。自動表示では従来どおり、拡大して薄れる文字を維持します。選択を外した情報は倍率にかかわらず非表示。表示設定はカメラや個人の履歴を書き換えません。

ホイール・ドラッグ・慣性移動、1本指の移動・2本指のピンチ、＋／−・全体表示、矢印・Home・Escapeに対応します。ラベル・問題文の上からもホイール・ドラッグ・ピンチが地図を操作します。キーボードでラベルを選択すると、その地域へ近づきます。動きを減らす設定ではアニメーションと慣性を省きます。

地図上の問題は半透明の白背景の問題文だけです。中央のカードは従来の文字サイズ・幅・最大7行を保ち、問題の点が画面の周辺にあるほど、滑らかに小さな文字・窓・余白・最大3行へ調整します。周辺の最小幅はPC136px／スマホ116px、文字はPC11.5px／スマホ11px。白背景の不透明度は78〜88%で、ホバー／フォーカス時は92%にして最前面に出します。長文の全文は詳細で読めます。

問題の候補は中央と選択中の問題を優先した後、離れた画面領域へ交互に枠を配ります。一地域で上限を使い切らず、周辺の小さなカードも使って多くの問題を表示します。カードは近くの複数候補位置から空きを探し、以前の位置は小さな移動を安定させる程度に優先します。カード同士は小さい方の面積の18%までの重なりを許し、操作ボタンの領域には重ねません。スマホは最大14枚、PCは最大44枚を上限とし、画面面積・実際に確保できる空きで件数を決めます。移動したカードが落ち着くまで描画を続け、退出カードのフェードは220msにして重なった残像を抑えます。文字幅と問題の計測結果をキャッシュして移動中の再計算を抑えます。

クリック・タップ・Enterで詳細を開き、全文・選択肢を表示します。「正解と解説を見る」で元JSONの解説を開けます。スクロールは詳細だけで行い、ドラッグやピンチで詳細が誤って開かないよう移動を判定します。詳細を閉じると元のページ位置・地図へ戻ります。密集する点からは近隣問題一覧も開けます。「この周りの問題を解く」は、選択中の問題と近隣の最大5問を距離順に選び、既存の `?challenge=<questionId,…>` に渡します。

## 個人成績・全体成績

成績切替の右に間隔を空けて「この地域を解く」を置きます。押すと円で出題地域を選ぶ確認画面を直接開き、範囲のモード切替は置きません。初期の中心は現在の地図の中心に保ち、現在の画面の対角線の半分を地理的な半径として円内に収めます。全体表示では全問題の中心からの最大距離を上限にし、画面の空白のために引きすぎないようにします。どちらにも4%の余白を加え、選択用の地図はその円に合わせて引いた倍率で始めます。

円をドラッグして移動し、ホイール・ピンチ・＋／−で地図を拡大縮小します。円は画面上で見やすい大きさを保ち、拡大すると地理的な半径が小さくなります。矢印キーで地域の移動、＋／−キーで拡大縮小も可能です。選択用のカメラは元の地図から独立させ、同じ地形・成績を描画します。サイズ変更時も円が選んだ地理的な範囲を保ちます。

候補は空間索引で全座標から取得し、円の中心からの距離が半径以下の問題だけを採用します。矩形の隅にある問題を混ぜず、重なり回避でカードを表示していない問題も含めます。円と候補件数は操作に合わせて更新し、候補が変わった場合だけ重複なしで最大5問を抽選します。既存アプリの `?challenge=<questionId,…>` へ渡し、5問以下なら全件を渡します。円内が空でも範囲の調整は続けられ、開始リンクを無効にして別の地域へフォールバックしません。全表示範囲が空の場合は地図下の起動ボタンを無効にします。再度開くと現在の地図の地域から始め直し、キャンセル時は元の地図・ページ位置・履歴を保ち、起動ボタンへフォーカスを戻します。

`info1LearningRecord:v1` の `q[id][0]`（回答回数）と `[1]`（正答回数）を読み取り専用で参照します。現在形式がない場合は `info1QuizStats:v4` の旧履歴も読みます。履歴を書き込んだり移行したりせず、消去済みの現在形式を旧履歴で上書きしません。未知ID・不正値は無視します。

近隣の回答回数と正答回数にGaussianの重みを掛け、正答回数／回答回数を背景色にします。低正答率は赤〜黄、高正答率は緑〜青、回答がない領域は中立色。問題の点にも個別の正答率を反映し、詳細には回答数と元の正答率を明記します。未挑戦を誤答として計算しません。`storage`、`pageshow`、ウィンドウへの復帰で更新し、他タブでの学習・履歴消去も反映します。

「個人成績」「全体成績」を地図下で切り替えます。全体成績は `question-stats.mjs` が学習アプリの `startup.js` から公開の読み取りAPI設定を取得し、同じ `get_question_stats` RPCを200問ずつ・最大2並列で読み込みます。送信するのは公開問題のIDだけで、個人の履歴・解答は送信しません。全バッチの取得後に切り替え、取得失敗時は未取得と再取得ボタンを表示します。個人成績を全体の値として表示しません。

個人・全体の両方で、凡例のすぐ右の小さな「0～100％／地域差強調」トグルを切り替えます。既定は個人が0〜100%、全体が地域差。切り替え時に説明文を出し入れせず、凡例の数値幅も確保して縦幅・配置を固定します。各成績で選んだ色範囲はページ内で独立して保持し、切り替えて戻ると復元します。色範囲の変更ではデータを再送信したり、カメラ・元の履歴を変えたりしません。

地域差では近隣の回答数で重み付けした地域正答率の5〜95パーセンタイルを色の範囲として使います。各1回の履歴がほとんどのユーザーでは周辺も0%／100%に偏りやすいため、色範囲の決定には近隣の回答が重なる領域を優先します。密度0.8以上かつ重み付き回答数4以上で32画素以上ある場合はその領域を使い、足りなければ回答数2以上、1以上へ順に緩めます。ヒートマップ自体の正答率は引き続き全回答から計算し、この条件で問題を除外しません。範囲の幅は最低16ポイントとし、均一な成績の微小な差を過度に強調しません。元の集計値・詳細の正答率は変更しません。凡例は「下限%・バー・上限%」とし、使用した実際の範囲を示します。未取得・未挑戦は中立色です。

海岸線は問題の座標密度の等高線から作ります。Gaussianの幅を座標の最大範囲の1.4%、密度の閾値を0.8として以前より輪郭を締めています。成績に依存せず、切り替えても地形は固定です。履歴は送信しません。共通のサイト解析・広告は既存Labと同じ構成です。座標の軸・遠い島同士の距離・島の面積を難易度や学習量として解釈しないこと、地形の色は近隣を混ぜた目安であることを画面に説明しています。

ユニット検証は実データ整合性、本文の改行差と変更の検出、空間索引、拡大中心の保持、段階の安定性、表示範囲に応じた用語変更、衝突回避、現行／旧履歴と消去、回答回数による地形の重み付け、海岸線の閉曲線と成績からの独立、全体成績の色範囲と元データ保持、カードの衝突緩和と位置の継続、ラベルの拡大・減衰、集計APIの正規化とバッチ失敗を確認します。ブラウザ検証は1280・390・320pxでヘッダーの自動選択・選択の反転・複数選択・手動でのズームと復帰、凡例横のトグル位置と縦幅の固定、地図・タグ・単語・問題文・詳細の原文一致・横溢れ・縁取り文字の拡大／減衰・問題文上のホイール／Ctrlホイール・ドラッグ／ピンチ、詳細のスクロール・閉じた後のページ位置、密集地点の複数カードと移動・深い拡大での表示継続、個人／全体の色と履歴保護・取得失敗、WCAGの自動検出可能な項目を確認します。ブラウザ検証の履歴はテスト専用コンテキストに注入し、外部の解析・広告リクエストは置き換えます。

配信時はポータルとアプリを同じオリジンに置きます。既存JSONを直接参照する構成を維持するため `catalog.mjs` の `standalone: false` で単体HTMLの書き出し対象から除外しています。

全体成績のブラウザ検証では、実APIの通信先だけをテスト応答に置き換え、成功・失敗と送信内容を確認します。作業環境のネットワーク制限により実DBへの通信は未検証です。公開コードと非公開Sitesでは、シミュレーションの全体成績は置かず実APIから読み込みます。

密度のブラウザ検証は、1280・390・320pxで手動のタグ・単語・問題を拡大して別の地域へ移動し、引いた後に元の地域の広がりへ戻ることを確認します。問題カードの表示数、中央／周辺の文字・幅、半透明の白背景、画面境界、重なりの割合、静止時にカードが入れ替わり続けないことも検証します。

地域出題のブラウザ検証は、同じ3画面幅でモード切替なしの起動、現在の地域が初期の円内に入ること、全体表示で引きすぎない上限、再起動時の初期化、描画された円と地図の座標変換から求めた候補件数・IDの一致、マウス／タッチのドラッグ、ホイール・Ctrlホイール・ネイティブのピンチ・拡大縮小ボタン、キーボード・フォーカス・ページ位置・履歴保持を確認します。少数／空の円内、5問の上限、元の地図の保持、実際の学習アプリの出題・正答・既存履歴への加算も確認します。320pxは高さ667pxの画面でも確認します。
