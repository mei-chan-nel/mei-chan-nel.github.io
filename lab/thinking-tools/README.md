# 思考ツールで問題解決を体験する

`/lab/thinking-tools/` のブラウザ内で完結する教材です。既存の共通CSS・Labのナビゲーションを使用し、ビルドや追加ライブラリは不要です。Lab入口の「情報デザイン」に教材カードを登録しています。

## 体験の流れ

1. 5W1Hで問題・課題を整理し、現状と理想のギャップ・測定指標を決める。
2. ブレーンストーミングで発言を出し、他の発言から発展させる。批判を控える・自由奔放・量を重視・結合改善の4原則を表示する。発言を意見・仮説としてKJ法のカードへ渡し、調査記録と区別して読み合わせ、チェックで選んでまとまりを作る。ドラッグや選択欄でも移動できる。表札・上位のまとまり・関係図・全体の文章説明を編集する。種類と出典は、重複する表示を置かず編集欄を常時表示。
3. 特性要因図の大骨・小骨を選択して図の隣で編集し、原因の候補に情報カードと確かめ方を結び付ける。原因のプリセットには次の発想で使う原因の選択も含め、手動の選択は上書きしない。KJのまとまりから大骨を作ることもできる。
4. 中心から左右に広がるマインドマップの枝を選択し、図の隣で子の枝を追加・編集・接続し直す。親から原因を引き継ぎ、具体案を比較候補にする。
5. 評価軸・重み・点数を編集して比較する。加重平均は未採点の軸がある案には出さない。試す案を自分で選んで担当・期間・検証方法を決める。
6. チェックシートと実施結果を記録する。「実施済み」を明示し、チェックは作業の実施記録で効果の証明ではないことを説明する。割合は件数を合計、数値指標は記録の平均で比較する。空欄を0に置き換えない。
7. KPTカードを編集・移動し、根拠と次の一歩を残す。Tryを発想の枝へ、検証の要約を情報カードへ戻して次の改善につなげる。

段階は自由に移動できます。まとめ済みの段階につながる上流データを編集すると、後の段階に変更した項目と変更前後の内容を示し、変更元へ戻れます。既存の作業は保持します。原因・カード・評価軸の削除では参照を整理し、マップの親の削除では子を一つ上へ接続します。

各段階の冒頭に、使うツールの名前・使い方・整理できるものを表示します。段階の終わりには現在の入力から整理結果と次へ渡す内容を示し、次の段階の冒頭では前の段階のまとめと引き継いだ内容を具体的に示します。前の段階へ戻る操作は段階ナビゲーションで行い、引き継ぎ欄の「前の内容を確認」ボタンは置きません。まとめ前の段階や未入力も区別し、途中からの利用・行き来・編集を妨げません。

## プリセットと自由作成

プリセットも空欄から開始し、各作業のそばの「プリセット記入」で、5W1H・ギャップ分析・調査カード・まとまり・原因図・発想の枝・採点・実施結果などを項目単位で追加します。基本の7段階は22回の記入操作で試せます。KJ法のカードのプリセットは、現在のブレーンストーミングの発言と9件の調査記録を一緒にカードへ記入します。自由作成でも発言ボードから個別・一括で渡せます。発言由来のカードと調査記録の区別・枚数を表示します。関係図と観察メモにはそれぞれ独立したプリセットを置き、採点には試す案の選択も含めます。後の項目を暗黙に記入しません。同じボタンが「空欄に戻す」に変わり、その操作で記入した部分だけ戻せます。既存の個別記入の保存内容も新しい項目ボタンから取り消せます。手動入力済みの内容は上書きしません。

プリセットの対象になった入力に一時的な緑の枠線を付けます。既定値の数え方・改善方向も対象に含め、カード・まとまり・関係線の編集行・評価軸・実施結果の行・KPTカードは外側の一枠に、比較表は表全体の一枠に揃えます。自動計算のギャップ・グラフ・順位の説明は囲みません。別の場所をクリックすると枠線が消え、次のプリセットでは新しい対象だけを囲みます。記入ボタンの位置を保ち、操作後に補足メッセージを増やしません。プリセットボタンは項目・入力欄の右上に置き、緑系、枝の追加や編集ボタンを白・青系に分けています。注目する点は各作業の短い案内に添えています。「操作のヒント」は表示しません。比較の案内は採点前から同じ場所に表示します。KJ法は単独のカードとまとまりを縦に分け、本文はラベルの重複をなくし、白背景・通常の枠線のコンパクトな記入欄にします。種類・出典の編集欄は常時表示します。図のプリセットは、上で整理したカードと表札を図として並べる操作で、上のまとまりの記入だけでは図を埋めません。関係線のプリセットを図の上に置き、図の目的・線がない状態での操作・つないだ情報から説明できることを表示します。関係の説明を編集すると読み取り内容も更新します。

題材は「学校の落とし物が持ち主に戻らない」。調査・点数・試行結果はすべて教材用の架空データです。「場所を知っている」と「自分の物だと認識する」の違い、受け取り時間、ためらい、記名、担当者の負担を考えられるようにしています。

4つの対策は効果・継続性・個人情報への配慮で競合し、重みを変えると順位が変わります。選んだ対策ごとに返却率・負担・課題の異なる架空結果を記録できます。品物は各週に集まった10件を4週間追跡する想定で、4週間の試行の最終確認は開始7週間後です。対策名・題材・指標・実施前の母数を変更した場合、用意された結果を自動で当てはめません。

自由作成は問題・ブレーンストーミングの発言・情報・原因・枝・評価軸・結果・KPTを完全な空欄から始めます。割合だけでなく、時間・件数など数値指標も使用できます。自由作成の実施結果は利用者が記録します。

## 保存・出力

- `localStorage` の `study-atlas.thinking-tools.v1.preset` / `.free` にモード別の作業を自動保存。直前に開いたモード・段階も再開する。
- JSONファイルのダウンロード・読み込み。ダウンロード開始時にファイル名・通常の保存先・ダウンロード一覧での確認方法を表示。バージョン・型・範囲・IDの参照・マップとKJのまとまりの循環を検証し、不正なファイルでは現在の作業を保持する。上限2MB、各リスト300件。未知の項目は取り込まない。
- 保存形式はv3。ブレーンストーミングの発言・発展元・KJへの接続も保存し、以前のファイルでは発言ボードを空として復元します。発言の削除やプリセットの取り消し後も、KJ法へ渡して編集した情報カードは保持します。関係図の表示状態を追加し、以前のファイルの図と観察メモを新しい独立した操作へ移行します。プリセット操作の取り消し対象と具体的な上流変更も保存し、再開後も操作できます。既存v1・v2の保存内容を移行して保持し、新規体験だけを空欄にする。ブラウザの保存キーは継続使用。
- 全段階の文章をMarkdownとして書き出し、全体表示から印刷・PDF保存できる。出典・確かさ・点数・測定条件・KPTの根拠も含む。
- ブラウザの保存が使えない場合はファイル保存を案内する。破損したブラウザ内の作業は、明示的なリセット・ファイル読み込みまで上書きしない。
- JSONからの文字列もHTMLとして解釈せず表示する。外部送信・共有サーバーは使わない。

## ファイルと検証

- `index.html`：共通ヘッダー・フッター、教材の入口、保存・出力操作。
- `thinking-tools.css`：レスポンシブなワークスペース・各ツール・印刷。
- `model.mjs`：教材データ、比較計算、段階の参照、ファイル検証、全文出力。
- `app.mjs`：編集UI、図、モード切替、自動保存、ファイル操作。

```sh
node lab/tools/build-pages.mjs --check
node scripts/thinking-tools.test.mjs
node --check lab/thinking-tools/app.mjs
python3 scripts/preview_site.py --host 127.0.0.1 --port 8773
```

モデルテストは空の自由作成、重みによる順位の変化、原因の継承、対策別結果、架空結果の適用範囲、未入力・不正な測定、改善方向、上流の変更、JSONの循環や不正な参照、全文出力を検証します。

ブラウザで確認する際は、両モードで7段階を操作し、保存・再読込、JSONの復元、不正ファイルの拒否、KPTからの再調査・再発想も確認してください。スマートフォンではカードの「このカードを置くまとまり」を使えます。原因図・マップは全体表示／拡大縮小に対応。枝はEnterで編集、Insertで子の枝、Shift＋Enterで同じ階層。KJのカード・まとまり・関係線、原因図の大骨・小骨、マップの枝はDeleteで削除。中心をDeleteすると、教材内の確認画面からその図を空にできます。リセット・読み込み・親の枝の削除も教材内の確認画面を使い、埋め込み環境の標準ダイアログやフォーム送信に依存しません。図・比較表は内部で横スクロールし、ページ全体を横にはみ出させません。

既存Labと同じく未公開の `noindex, nofollow` を継承しています。サイト全体トップ・サイトマップ・公開設定は変更していません。

ブラウザの統合テストは `scripts/thinking-tools-browser.cjs` です。別途Playwrightとaxe-coreを導入したテスト環境で、上のプレビューサーバーを起動して実行します。

```sh
NODE_PATH=<テスト環境のnode_modules> THINKING_TOOLS_BROWSER=<Chromiumの実行ファイル> node scripts/thinking-tools-browser.cjs
```

Playwright標準のブラウザを使う場合は `THINKING_TOOLS_BROWSER` を省略できます。別のプレビューURLには `THINKING_TOOLS_URL` を指定します。テストは独立したブラウザの作業で両モードを操作し、項目単位の記入・枠線・ボタン位置の維持、ドラッグ、原因の接続、枝の発想、評価と検証、KPTからの循環、ファイル復元、印刷、390pxでの表示、7段階のアクセシビリティ、保存不可・破損保存時の扱いを確認します。`allow-modals`と`allow-forms`を持たないsandbox iframeでも、プリセットの再開・取り消し、各図形や線のDelete、具体的な変更通知、JSONダウンロード、リセットを確認します。試験用ファイルは一時フォルダーに置き、終了時に削除します。

## KJ法の扱い

[川喜田研究所の公式説明](https://kj-kawakita.co.jp/about_kj-method/)と[手順資料](https://www.everfield.co.jp/KJ/step.html)を確認。先にカテゴリーを決めて振り分ける体験から、ラベル作成→内容を読み合わせて表札作成→関係の図解→文章化へ変更しました。「種類」は情報の性質、「まとまり」は内容が語る共通の意味です。単独の情報を無理にまとめず、異なる種類も読み合わせられます。例のまとまりは正解判定に使いません。

調査に用いた参考リンクはこの開発資料に残しています。教材画面の簡略化の説明・参考リンクの段落は表示しません。

ツールの案内・具体的な引き継ぎ・右上の記入操作・ブレーンストーミングの両モード操作は `scripts/thinking-tools-teaching-browser.cjs` でも検証します。発言の追加・発展・即時の受け渡し・出典と種類の保持・削除・再開・取り消し・スマートフォンでの表示を確認します。
