# 色覚シミュレーター

`/lab/color-vision/`。既存Interactive Labの書体・配色・ヘッダーに合わせた、依存パッケージ不要の静的教材です。`feat/color-vision-simulator`で制作し、公式サイトのmainは変更しません。

## 学習内容

題材は独自制作の架空の「青葉祭・当日案内ページ」1点。通常・P型・D型・T型の**現在の画像4枚を2×2**で比較します。改善前と改善後を同時には表示しません。

各回は「拡大して観察」「改善する」「全体を見る」の3つの操作です。直前のデザインを変えずに対象箇所へ寄り、同じ拡大位置のまま、その箇所だけを改善します。「全体を見る」は改善後のデザインを保持し、倍率を100%に戻します。最後の「完成品を見る」では、8つの改善後のページ全体を注目枠なしで表示します。初期状態＋8回×3操作＋完成品の26画面を、左側の工程から自由に選べます。受付状況は1つのカードにまとめ、各改善の対象は必ず1領域に限定しています。

| 改善 | 変更する1箇所 | 内容・学習上の注意 |
| --- | --- | --- |
| 1 状態表示 | 受付状況のカードと直上の凡例 | 凡例と受付欄の両方で、青い○ 受付中／濃いオレンジの■ 受付終了をそろえる。 |
| 2 パネルの配色 | 案内パネルのカード | 会場色を青／オレンジ／濃い紫へ。飲食の白文字の明暗差は不足するため、次の工程で改善する。 |
| 3 パネルの文字 | 案内パネルのカード | 背景色を維持し、オレンジだけ濃い文字へ。会場名・固定位置の区切り線・内容を列でそろえる。 |
| 4 お知らせ | お知らせ帯 | 文字を濃くし、「重要」の語を加える。 |
| 5 文字と背景 | 右上の注意パネル | 赤系文字と緑系背景の比率1.04:1を、淡い背景と濃い赤文字の7.80:1へ改善する。 |
| 6 会場案内図 | 地図のカード | 案内パネルと同じ会場色・模様・白地の会場名を使い、凡例の分類情報も残す。ABCは使わない。 |
| 7 タイムテーブル | 時刻表のカード | 会場名を独立した列に表示し、色帯を地図・案内パネルとそろえる。 |
| 8 グラフ | 混雑予想グラフのカード | 凡例を維持し、配色・線種・点と、重ならない直接ラベルを1工程で追加する。 |

各工程の妥当性、今回修正した内容と残る改善余地は[内容レビュー](./README-content-review.md)に記載しています。工程2は配色の改善であり、飲食の白文字に生じた明暗差の低下は工程3で解消します。工程3では背景色を薄くしません。会場名・会場色は共通のVENUESデータから描画し、ABCは使いません。地図の凡例は会場名と催しの分類を併記します。案内パネルは地図の右、時刻表はその下へ配置します。

説明は比較カードの右側に幅220pxで、工程は画像の左側に置きます。画面幅1,100px以下では説明をカードの下へ回します。全体と部分拡大を往復でき、倍率・ドラッグ・キーボード移動は4枚で同期します。観察と改善では、カメラ位置と倍率をそろえます。

- 左端の「全画面」で、比較カードと説明欄を含む作業領域が画面内に収まります。説明は右側の幅220px、画面幅800px以下では下側に置き、内容が長い場合は説明欄の中でスクロールできます。Fullscreen APIが利用できない埋め込み環境では、同じ大きさのページ内表示を使います。全画面のまま工程の選択、説明・手法の確認、画像の個別拡大ができます。
- 各画像のクリック／タップ、画像にフォーカスしてEnterまたはSpaceで、その画像を大きなダイアログに表示します。見出しに拡大ボタンは置きません。ドラッグ後はダイアログを開きません。
- 個別拡大では注目箇所をダイアログに収め直し、閉じたら元の4枚のカメラを復元します。Escまたは閉じるボタンで戻れます。
- 「全体に戻す」でページ全体を確認できます。各工程のハイライトは1箇所のみです。

## 色覚モデル

Brettel, Viénot & Mollon (1997), *Computerized simulation of color appearance for dichromats*, DOI: [10.1364/JOSAA.14.002647](https://doi.org/10.1364/JOSAA.14.002647)。P・D・T型すべてに2投影面を使います。完全な2色覚の近似であり、色弱の程度のスライダーや、シミュレーションでの適合判定は実装しません。

係数はNicolas Burrusの[libDaltonLens](https://github.com/DaltonLens/libDaltonLens/blob/master/libDaltonLens.c)（Public domain / Unlicense）。sRGB標準とSmith–Pokorny 1975 LMS、RGB白を中立軸とする係数を使用します。

1. ブラウザのsRGB Canvasに描画。自分の画像の透明部分は白に合成する。
2. sRGB伝達関数の逆変換で線形RGBへ変換する。
3. 分離面の内積を判定し、対応する投影行列を適用する。
4. 表示域へクリップしてsRGBへ戻し、8bitへ四捨五入する。

初期ページの赤／緑は、このモデルのP・D列で色差が小さくなります。変更後の青／オレンジは区別がつきやすくなりますが、色差の数値を知覚の閾値や合否として扱いません。T列では地図の青／緑が近づくため、地図のA/B/Cと模様にも意味があります。

飲食パネルの文字と背景のWCAG相対輝度比は `白 / #567658 = 5.09:1` → `白 / #e69f00 = 2.25:1` → `#203b40 / #e69f00 = 5.29:1`。比率は**元のsRGB値**から計算し、シミュレーション画像の値では判定しません。小さな画面、視力、実際の利用者の見え方も含めて確認が必要です。

グラフの模擬店の線は `#758b4b / 白 = 3.78:1` → `#a66b00 / 白 = 4.44:1`。凡例を維持し、直接ラベルは引き出し線で上下に分けます。意味を伝える線と背景は3:1が目安で、通常文字の4.5:1とは区別します。補助文字も背景に4.5:1以上を確保しています。

右上の注意パネルは `#c66f4a / #758b4b = 1.04:1` → `#8a2931 / #fff1ed = 7.80:1`。赤と緑が常に不適切なのではなく、実際の明暗差とシミュレーションを確認する例です。

## 自分の画像

- PNG・JPEG・WebP、20 MiB以下、4,000万画素以下。
- 長辺1,600pxを上限に縦横比を保って縮小する。縮小した場合は元の寸法と処理寸法を表示する。
- ファイルはObject URL経由でデコードし、変換はWeb Workerで実行する。Worker非対応の場合は型ごとにイベントループを挟んでブラウザ内で変換する。
- サーバーへのアップロード、外部API、解析、永続保存は使わない。Object URLは読込後に破棄する。新しい入力が来た場合は古い結果を適用しない。
- 現状のみ2×2で表示する。4種類を2×2にまとめたPNGと、通常／P／D／Tの個別PNGを書き出せる。表示位置に関係なく処理した画像全体を保存する。出力には手法と近似の注記を付ける。
- 削除またはリロードで画像を破棄する。学習モードとの切り替え中は、選択したステップと読込画像を保持する。

## 検証

```sh
node lab/color-vision/simulation.test.mjs
node lab/tools/build-pages.mjs --check
git diff --check
```

`reference-fixtures.json`は2026-10-15に取得した上記の公開C実装をコンパイルし、2色覚・severity 1.0で生成した102色×3型の参照値です。両投影面をカバーします。C実装の非線形sRGB符号化は切り捨て、JavaScriptは四捨五入のため、最大1階調の許容差で照合します。追加で全256段階の無彩色・sRGB往復、アルファ保持、既知のコントラスト比と教材の配色の関係を検証します。

ブラウザ検証では、8つの改善について元画像のピクセル差分を計測し、指定した1領域以外の変化が0画素であることを確認します。各回の3つの操作、観察が直前のデザインを保持すること、観察と改善でカメラが変わらないこと、全体表示で改善後の画像を保持すること、4枚の同期移動、クリックとドラッグの区別、4種類すべての個別拡大、キーボード操作、説明の右配置・工程の左配置・2×2の配置も確認しています。

全画面は1228×607、940px、390px、320pxで比較カードと説明欄が画面内に収まること、説明のスクロール、工程切り替え時の説明位置のリセット、埋め込み環境向けの代替表示を検証します。完成品と8つ目の改善後の画像が一致し、注目枠を外して全体を表示することも確認します。画像読込・白背景合成、モード保持、5種類のPNG寸法（まとめ画像は2×2）、外部リクエストとJSエラーの不在、axeの重大なWCAG A/AA違反も確認します。シミュレーション対象のページは学習用の問題を含むため、教材UIと区別します。
