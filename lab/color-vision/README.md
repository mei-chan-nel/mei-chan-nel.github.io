# 色覚シミュレーター

`/lab/color-vision/`。既存Interactive Labの書体・配色・ヘッダーに合わせた、依存パッケージ不要の静的教材です。公開先は`https://mei-chan-nel.com/lab/color-vision/`、公開元は公式サイトの`main`です。所有者限定のSitesはレビュー用として保持します。

## 学習内容

題材は独自制作の架空の「青葉祭・当日案内ページ」1点。通常・P型・D型・T型の**現在の画像4枚を2×2**で比較します。改善前と改善後を同時には表示しません。

各回は「拡大して観察」「改善する」「全体を見る」の3つの操作です。直前のデザインを変えずに対象箇所へ寄り、同じ拡大位置のまま、その箇所だけを改善します。「全体を見る」は改善後のデザインを保持し、倍率を100%に戻します。最後の「完成品を見る」では、8つの改善後のページ全体を注目枠なしで表示します。初期状態＋8回×3操作＋完成品の26画面を、左側の工程から自由に選べます。受付状況は1つのカードにまとめ、各改善の対象は必ず1領域に限定しています。

| 改善 | 変更する1箇所 | 内容・学習上の注意 |
| --- | --- | --- |
| 1 状態表示 | 受付状況のカードと直上の凡例 | 凡例と受付欄の両方で、青い○ 受付中／濃いオレンジの■ 受付終了をそろえる。 |
| 2 パネルの文字 | ご来場のヒント | 全行を同じ黄色で統一し、矢印は置かない。白文字から濃い文字へ1.32→9.01:1。情報と配置は変えない。 |
| 3 お知らせ | お知らせの文字部分 | 文字を濃くし、「重要」の語を加える。 |
| 4 文字と背景 | 右上の注意パネル | 赤系文字と緑系背景の比率1.04:1を、淡い背景と濃い赤文字の7.80:1へ改善する。 |
| 5 会場案内図 | 地図のカード | 通行止めに×・破線・直接ラベル・斜線区画を加え、通れる道に矢印を付ける。建物・会場名・色は変えない。 |
| 6 建物の見分け | 地図の建物部分 | P・D列で近づく青／紫を、斜線／点／格子と名前で区別。建物色は時刻表と共通のまま。 |
| 7 タイムテーブル | 時刻表のカード | 会場名を独立した列に追加。色帯・時刻・催し名は維持する。 |
| 8 グラフ | 混雑予想グラフのカード | 凡例を維持し、配色・線種・点と、重ならない直接ラベルを1工程で追加する。 |

各工程の妥当性と残る改善余地は[内容レビュー](./README-content-review.md)に記載しています。旧「どこへ行こう？」は会場一覧をやめ、入場・食券・落とし物の「ご来場のヒント」に変更。地図と内容が重ならない役割にしています。パネルの全項目は同じ黄色で、矢印は使いません。改善では文字と区切り線の色だけを変えます。会場の色との対応を表すパネルではありません。

地図はL字型の校舎、体育館、中庭、正門、トイレを配置した平面図です。地図の改善は通れる道と通行止めを色以外で判断し、迂回方向をたどる工程。通行可＝緑／通行止め＝赤は全状態で維持し、凡例と本体の記号をそろえます。会場名・会場色は共通のVENUESデータから地図と時刻表へ描画し、ABCは使いません。体育館＝青、中庭＝紫、校舎＝灰色で、P・D列で近づく青／紫には建物の模様を加える独立工程を設けています。地図の右を来場案内、その下を時刻表にしています。

ページ末尾の「学習のポイント」はネイティブのdetails/summaryで折りたたみます。赤／緑、青／紫、青／緑、明るい背景と白文字、明暗差の小さい文字と背景について、見え方と改善方法を一覧にしています。初期状態は閉じ、キーボードでも開閉できます。

お知らせの注目範囲は横長の帯ではなく、文字を含む560×54px。観察・改善・個別拡大のいずれでも同じ文字部分に寄ります。

説明は比較カードの右側に幅220pxで、工程は画像の左側に置きます。画面幅1,100px以下では説明をカードの下へ回します。全体と部分拡大を往復でき、倍率・ドラッグ・キーボード移動は4枚で同期します。観察と改善では、カメラ位置と倍率をそろえます。

- 左端の「全画面」で、比較カードと説明欄を含む作業領域が画面内に収まります。説明は右側の幅220px、画面幅800px以下では下側に置き、内容が長い場合は説明欄の中でスクロールできます。Fullscreen APIが利用できない埋め込み環境では、同じ大きさのページ内表示を使います。全画面のまま工程の選択、工程説明の確認、画像の個別拡大ができます。
- 各画像のクリック／タップ、画像にフォーカスしてEnterまたはSpaceで、その画像を大きなダイアログに表示します。見出しに拡大ボタンは置きません。ドラッグ後はダイアログを開きません。
- 個別拡大では注目箇所をダイアログに収め直し、閉じたら元の4枚のカメラを復元します。Escまたは閉じるボタンで戻れます。
- 「全体に戻す」でページ全体を確認できます。各工程のハイライトは1箇所のみです。

## 色覚モデル

Brettel, Viénot & Mollon (1997), *Computerized simulation of color appearance for dichromats*, DOI: [10.1364/JOSAA.14.002647](https://doi.org/10.1364/JOSAA.14.002647)。P・D・T型すべてに2投影面を使います。完全な2色覚の近似であり、色弱の程度のスライダーや、シミュレーションでの適合判定は実装しません。

係数はNicolas Burrusの[libDaltonLens](https://github.com/DaltonLens/libDaltonLens/blob/master/libDaltonLens.c)（Public domain / Unlicense）。sRGB標準とSmith–Pokorny 1975 LMS、RGB白を中立軸とする係数を使用します。

1. ブラウザのsRGB Canvasに描画。自分の画像の透明部分は白に合成する。
2. sRGB伝達関数の逆変換で線形RGBへ変換する。
3. 分離面の内積を判定し、対応する投影行列を適用する。
4. 表示域へクリップしてsRGBへ戻し、8bitへ四捨五入する。

経路の赤／緑はP・D列、建物の青／紫はP・D列、グラフの青／緑はT列で近づく例です。見え方を「赤と緑だけの問題」としないため、異なる情報構造と組み合わせで扱います。色差の数値を知覚の閾値や合否としては扱いません。建物では色を変えず、斜線・点・格子と会場名を使う改善を学びます。

「ご来場のヒント」は全行を同じ黄色`#ffdf36`にし、白から`#203b40`の文字へ変更します。全行とも **1.32→9.01:1**。比率は元のsRGB値から計算し、シミュレーション画像の値では判定しません。

グラフの模擬店の線は `#45a58e / 白 = 2.99:1` → `#a66b00 / 白 = 4.44:1`。凡例を維持し、直接ラベルは引き出し線で上下に分けます。意味を伝える線と背景は3:1が目安で、通常文字の4.5:1とは区別します。補助文字も背景に4.5:1以上を確保しています。

右上の注意パネルは `#c66f4a / #758b4b = 1.04:1` → `#8a2931 / #fff1ed = 7.80:1`。赤と緑が常に不適切なのではなく、実際の明暗差とシミュレーションを確認する例です。

## 自分の画像

- PNG・JPEG・WebP、20 MiB以下、4,000万画素以下。
- ファイル選択とドラッグ＆ドロップに対応。上部の枠だけでなく、空の比較エリア・読み込み済み画像・全画面表示にも1枚ずつドロップできる。ファイルをドラッグしている間はドロップ案内を表示する。複数ファイル・非対応形式は既存画像を保持してエラーを示す。学習モードではドロップで移動・読込しない。
- 長辺1,600pxを上限に縦横比を保って縮小する。縮小した場合は元の寸法と処理寸法を表示する。
- ファイルはObject URL経由でデコードし、変換はWeb Workerで実行する。Worker非対応の場合は型ごとにイベントループを挟んでブラウザ内で変換する。
- 画像処理のためのサーバー送信、外部API、永続保存は使わない。公開ページでは他のLabと同じサイト共通のアクセス解析・広告を読み込むが、画像の読込・変換・保存はブラウザ内で行う。Object URLは読込後に破棄する。新しい入力が来た場合は古い結果を適用しない。
- 現状のみ2×2で表示する。4種類を2×2にまとめたPNGと、通常／P／D／Tの個別PNGを書き出せる。表示位置に関係なく処理した画像全体を保存する。出力には手法と近似の注記を付ける。
- 削除またはリロードで画像を破棄する。学習モードとの切り替え中は、選択したステップと読込画像を保持する。

## 検証

```sh
node lab/color-vision/simulation.test.mjs
node lab/tools/build-pages.mjs --check
git diff --check
```

`reference-fixtures.json`は2026-10-15に取得した上記の公開C実装をコンパイルし、2色覚・severity 1.0で生成した102色×3型の参照値です。両投影面をカバーします。C実装の非線形sRGB符号化は切り捨て、JavaScriptは四捨五入のため、最大1階調の許容差で照合します。追加で全256段階の無彩色・sRGB往復、アルファ保持、既知のコントラスト比と教材の配色の関係を検証します。

ブラウザ検証では、8つの改善について元画像のピクセル差分を計測し、指定した1領域以外の変化が0画素であることを確認します。各回の3つの操作、観察が直前のデザインを保持すること、観察と改善でカメラが変わらないこと、全体表示で改善後の画像を保持すること、4枚の同期移動、クリックとドラッグの区別、4種類すべての個別拡大、キーボード操作、説明の右配置・工程の左配置・2×2の配置も確認しています。

全画面は1228×607、940px、390px、320pxで比較カードと説明欄が画面内に収まること、説明のスクロール、工程切り替え時の説明位置のリセット、埋め込み環境向けの代替表示を検証します。完成品と8つ目の改善後の画像が一致し、注目枠を外して全体を表示することも確認します。ファイル選択とDataTransferによる各領域へのドロップ、全画面でのドロップ、非対応形式・複数ファイルの拒否、白背景合成、モード保持、5種類のPNG寸法（まとめ画像は2×2）、画像を送信するリクエストとJSエラーの不在、折りたたみのキーボード操作・開いた状態の320pxでの折り返し・axeの重大なWCAG A/AA違反も確認します。シミュレーション対象のページは学習用の問題を含むため、教材UIと区別します。

工程説明は「変更した箇所と内容」「改善できたこと」の2項目。「残る問題」「新たに生じた問題」の表示・データと、比較カード下の常設案内文を削除した。近似の注意・手法・出典・画像の扱いは「学習のポイント」にまとめ、手法の詳細はその中で折りたたむ。ページ上部の手法リンクも同じ説明を開く。処理状況は読み上げ用の通知とし、ファイル名・処理寸法は画像選択欄の下に表示する。
