# パケット通信とルーティング

入口は `/lab/packet-routing/`。HTML/CSS/ES modulesのみで動き、依存パッケージ・外部API・サーバー側処理は不要です。Lab一覧のネットワーク分野から開けます。

## 操作

20台のルータ、6つのLAN、8台のPCを配置済みです。R13は故障、R7—R8は切断済みで、初期テーブルはそれらを検知・学習済みです。

左の送信欄（スマートフォンでは図の上）の送信元・宛先カードを押し、図のPCかPCカードを選んで指定します。メッセージは12文字ずつに分割して送ります。「連続送信」は内部時間で2.8秒間隔。「経路上の回線を切断」は転送中の回線、または送信元側の経路を選び、消失と復旧の比較を始めやすくします。

図の機器・回線を選ぶと、対象の近くに小さな操作メニューを表示します。PCでは「送信元にする」「宛先にする」、稼働中の機器では「故障させる」、回線では「切断する」、停止中では「復旧する」を表示します。ルータのテーブルはメニュー内の「ルーティングテーブル」で開きます。IP・接続先・削除・回線コストは「詳細・削除」にまとめています。送信とパケット追跡はサイドバー、機器の操作は図内に置きます。

図の左上「機器を追加」からルータ・LAN・PCをドラッグして追加します。本体のドラッグは選択・移動、選択中の機器を囲むサークルから相手へのドラッグは回線接続です。サークルに重ねたカーソルは＋になります。接続できる相手を緑で強調します。サークルの操作範囲は拡大率に応じて調整し、タッチでも操作できます。キーボードでは追加ボタン→図の余白、または図にフォーカスしてEnterで配置できます。機器にフォーカスしてCを押し、接続先でEnterを押すと配線できます。矢印キーは機器・表示の移動、Escは操作の終了。余白のドラッグ・ホイール・拡大縮小ボタン・ピンチにも対応します。

通信と経路更新は一定の速さで自動で進みます。再生・停止・ステップの操作と経過秒数の表示はありません。パケットを選ぶと実際の通過経路・各判断のテーブル版・消失原因を表示し、「図で追う」でカメラが追従します。消失時は図に赤い×と「消失」を表示し、原因付き通知を閉じるまで保持します。「原因を確認」で消失したパケットの経路と判断を表示できます。結果も「パケット消失」と個数を明記します。結果は20メッセージ、追跡用は最近の200完了パケットと通信中の全パケット、履歴は600件まで保持します。到達・消失カウンターは実験全体を数えます。

履歴とルータの判断は、発生時に取得したブラウザの現在時刻（時・分・秒）を表示します。日時を保存し、後から表示を変更しても時刻は書き換えません。遅延の計算用の内部時間と、表示用の実時刻は独立しています。外部APIや時刻サーバーは使いません。

## モデル

`simulator.mjs`はDOMに依存しない離散イベントモデルです。転送と収束の計算は決定的で、表示用の実時刻は`now`関数を注入してテストできます。`app.mjs`がrequestAnimationFrameで内部時間を自動で進め、SVGの位置を補間します。モデルの`step()`はテスト用に残しています。同時刻のイベントはまとめて処理します。消失位置も消失時に補間して保存し、後から機器を削除しても場所が失われません。

単一エリアのOSPFを参考にしたリンクステート方式で、各ルータに独立したLSDB、広告のシーケンス番号、SPFによるテーブルを持たせます。検知に2.4秒、隣へのLSA伝達に0.75秒、SPFに0.4秒を設定しています。端点が新しい自分の接続情報を広告し、受信側は新しい版だけを採用して再転送します。復旧・新規接続時には隣同士が持つ情報を交換します。ルータの再起動ではそのルータのDBとテーブルを消去して学習し直します。

各ルータは自分のDBの双方向隣接関係だけを使い、コストの合計が最小の経路を計算します。実際の転送はそのルータのテーブルを参照し、送信時点で使えない回線に対して別経路を先読みしません。転送中の回線切断・機器故障ではそのパケットを即時に消失させます。検知前の古いテーブルによる消失、一時的な経路の循環、TTL（32回）による破棄を再現します。パケットの通過経路・判断は個別に保存し、メッセージは全片が到達した場合だけ組み立てます。

図の破線は「現在の各ルータのテーブルをたどった予測」。追跡時の実線はパケットの実際の通過経路と移動中の回線です。LSAはオレンジの点、データは青い点で表します。

学習用の簡略化として、LANは1台のルータに接続し、PCは1つのLANに接続します。IPは10.0.<LAN番号>.0/24の範囲で自動設定します。回線コストは1〜9、機器数は80まで。OSPFのエリア分割、DR/BDR、認証、実際のパケット形式、定期HelloやLSAの経年失効、帯域制限、混雑、TCP、再送は扱いません。検知はトポロジー変化からの遅延イベントで代用しています。削除・到達不能になったルータの古いLSAはDBに残りますが、双方向接続がなくなるためSPFで経路には使えません。独立したテーブルが収束する過程を観察するためのモデルで、実機のOSPF実装ではありません。

## 確認

```sh
node --test scripts/packet-routing.test.mjs
node lab/tools/build-pages.mjs --check
python3 scripts/preview_site.py --host 127.0.0.1 --port 8773
```

ブラウザで `http://127.0.0.1:8773/lab/packet-routing/` を開きます。サイトの共通CSS・Lab用ナビゲーションを使い、広告・解析コードは読み込みません。

モデルの16テストでは、転送中の消失、検知前の古いテーブル、ルータごとの更新時刻、分断・復旧、ルータ再起動、ネットワーク追加・削除、コスト変更、TTL、メッセージ再構成、保存数の上限、実時刻の保存、途中の消失位置を確認します。複数障害の反復テストでは、収束後の各ルータのテーブルを独立した物理グラフの最短距離計算と照合します。

Chromiumで図・カードからのPC選択、自動通信・連続送信・消失・迂回、機器のドラッグ追加・移動、サークルからの接続と不正な接続の拒否、追加PCへの到達、履歴の実時刻、消失通知からの追跡を確認しました。タッチイベントによる追加・移動・接続も確認しています。1440px・390px・320pxの表示で横方向のはみ出しがなく、初期画面・図内の操作メニュー・消失追跡の画面はaxe-coreのWCAG 2 A/AA・2.1 AA自動チェックで指摘なし。実機Safari・Firefoxでの確認は未実施です。
