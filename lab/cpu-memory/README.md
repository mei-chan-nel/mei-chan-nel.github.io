# CPUと記憶装置

RAMの初期内容を書き換え、「次へ」で1動作ずつ進め、必要に応じて自動実行でCPUとキャッシュを観察する教材。Labの「アルゴリズム」に登録。

- RAMは0〜31番地。命令と数値を自由に配置。計算中の値は初期値0の1個。
- 命令は値の設定・読み出し・加算・減算・書き込み・無条件分岐・0の場合の条件分岐・終了の8種類。加算・減算は指定番地を参照し、値の設定は即値を使う。
- Studioで使用している `selection` / `field`（`expression-editor.js`）を再利用。日本語の命令選択と数値の直接入力に対応。番地ごとの入力補助ボタンは設けない。
- RAMの一覧は番地と現在の内容だけを表示し、行から初期内容の編集ダイアログを開く。編集や設定変更の確定時には初期RAMからCPU・キャッシュ・計測をリセット。比較記録は保持。
- 命令取得・データ読み出し・データ書き込みで1個の全相連キャッシュを共有。2番地固定のブロック、1・2・4・8・16個から容量を選択（初期2個）。全参照でLRU更新。
- 書込ミスはライトアロケート。書込は毎回RAMにも反映するライトスルー。命令を数値で上書きした場合もキャッシュとRAMは一致。
- ミス理由は初回と容量不足を区別。各命令のアクセスを選ぶと、その時点までの記録と置換理由を表示。通常の表示では現在の段階の状態だけを示す。
- 時間はCPU処理、キャッシュ参照、RAM転送を個別設定。2番地のブロック取得は1転送とする。ヒット率はCPUからの論理アクセスに対する割合。RAM転送回数は取得・書込を別計上。
- 合計時間 = 命令数 × CPU処理時間 + メモリ待ち。ヒットはcache、読出ミスはcache+RAM、書込ヒットはcache+RAM、書込ミスはcache+RAM×2。OFFは各アクセスRAMのみ。表示速度は仮想時間と独立。
- 上部の「読込」「保存」は論理回路ラボと同じ選択式メニュー。「読込」は5種類のプリセット・名前を付けてブラウザ内に保存したプログラム・JSONを選択。「保存」はブラウザ内保存（上書き／別名）・JSON書出を選択。名前付き保存は自動保存や比較記録とは独立し、初期RAMと設定を保存する。以前のversion 1 JSONも読込可能。
- 同じ初期条件からのON/OFF一括比較、最大12件の結果保存・削除・条件復元。作業中のプログラムと比較記録はブラウザ内に自動保存。
- 比較の条件番号は初期RAMと開始番地でグループ化。各記録には全設定・初期RAM・最終RAM・計測値を保存。途中の結果には「途中」を明示。
- 不正な番地・命令位置・非数値データ参照・整数の範囲超過を検知。自動実行は10,000命令ごとに停止、一括比較は10,000命令で終了しなければ記録せず理由を表示。

実機のパイプライン・先読み・転送の重なり・クロックやバス、補助記憶装置を省いた教材モデル。キャッシュの有無で最終計算結果が変わらないことを重視する。

## 表示と操作

CPU → キャッシュ → 主記憶装置（RAM）の順で配置。実行操作はプログラムトレースと同じ「→ 次へ」を主操作にし、「最初から」「自動実行／一時停止」「実行速度」「全画面」を並べる。操作ボタン・速度入力の表示はプログラムトレースに合わせ、`createAutoplay` / `adjustInterval` / `intervalSeconds` と `bindStepKeys` を同じソースから再利用する。速度は0.001秒以上、0.1秒以上は0.1秒刻み。Space／Enterでも1動作ずつ進められる（入力欄・ボタン・ダイアログ操作中は除外）。RAMは実行した命令を緑（`#eaf3ec` / `#267765`）、読出元を薄い赤（`#fce8e6`）、書込先を緑（`#cee6d5`）で表示し、プログラムトレースの実行行・参照元・代入先の配色に合わせる。

「全画面」は既存の同じDOMを表示領域いっぱいに広げ、RAM・CPU・キャッシュ・実行操作・計測値を表示する。ネイティブFullscreen APIが利用できない埋め込み環境でも同じページ内表示が使える。狭い画面はCPUとキャッシュを上、RAMを下に配置し、各パネル内をスクロールする。全画面ではプログラム名・上部操作バー・説明行・RAMの脚注を隠し、左の縦ツールバーへ終了・次へ・前へ・最初から・自動実行・速度・読込・保存・比較を配置。下部は計測値だけを小さく表示し、RAMと各パネルの縦幅を確保する。速度設定と比較記録は必要なときに重ねて開く。全画面を終了すると元の開閉状態・ページ位置・フォーカスを戻す。実行状態・キャッシュ・編集内容・比較記録は切替でリセットしない。「元に戻す」またはEscapeで終了し、ダイアログがある場合は先にダイアログを閉じる。

RAMは「番地」「現在の内容」の2列。行のクリック、または内容ボタンのEnter／SpaceでStudioと同じ行編集ダイアログを開く。種類と値／対象番地はStudioの共通入力部品を再利用し、現在の実行値を表示しながら初期内容を編集する。反映時だけ実行状態・キャッシュ・計測値・戻る履歴を初期化し、キャンセルでは変更しない。実行中の書込結果を初期RAMへ自動的に取り込まない。ダイアログを閉じると元の行へフォーカスを戻す。省いた列の幅はCPU・キャッシュに割り当てる。

アクセスを選ぶと、パネル間の矢印と番号付きの転送説明を更新する。矢印は「青い破線＝番地の要求」「緑の実線＝命令・データの転送」に統一し、命令取得・読出・書込で色の意味を変えない。矢印の先端・着点・送受信欄の枠・転送説明・凡例にも同じ規則を適用する。RAMの実行行・参照元・代入先の色はプログラムトレースと共通のまま。CPU → キャッシュへの要求とヒット／ミス判定を同じ1動作で表示し、ミス時はキャッシュ側からRAMへの要求、RAM → キャッシュのブロック取得、キャッシュ → CPUへの取込と進む。書込ではブロック確保後にCPU → キャッシュ、CPU → RAMの順に、同じCPUの書込値の反映を表示する。OFFではCPU → RAMへの要求と直接転送を示す。要求先はキャッシュの要求欄またはRAMの番地、命令はCPUの「現在の命令」、読み出した数値は「CPUが受け取った値」、書込元は計算中の値に結び、スクロール・サイズ変更・全画面切替で矢印を再配置する。キャッシュ枠にはキャッシュ制御を含めて表現し、実機のメモリコントローラやバスの配線は省略する。

CPUの進行説明パネル・ヒット／ミスのポップアップは設けない。各アクセスの最初のクリックでCPU → キャッシュの要求矢印と、キャッシュ要求欄のヒット／ミスを同時に表示する。要求欄は「17番地 · データ読出 · ヒット」の形式で、ヒットを緑の太字、ミスを赤の太字にする。判定だけの追加ステップは設けない。再描画だけで新たなアクセスや時間を計上しない。CPU → キャッシュはパネル間の短い曲線でつなぎ、上部の迂回経路やポップアップ用の余白は設けない。要求の矢印は文章から分けた受け口を着点にする。全画面、スクロール、リサイズでも矢印は受け口に追従する。命令の実行開始はCPUの命令欄の強調で示す。スクリーンリーダーへの動作通知は既存のステータス欄を使い、全画面でも読み上げを残す。

## 段階実行

`Machine.advance()` は1動作だけを進める。CPUからの命令要求とキャッシュ判定 → ミス時のRAM要求とブロック取得 → CPUへの命令取込 → 命令の実行開始 → データの要求・キャッシュ判定 → 必要ならRAM要求とブロック取得 → CPUへの数値取込 → 計算結果の反映／命令完了、と順番に観察できる。受け取った数値は計算中の値とは分け、次の動作で反映する。CPUの「CPUが受け取った値」は完了した命令数の直上に常時表示し、未受信時は「—」を表示する。開始番地の選択は廃止し、読込・初期化・条件復元も含めて0番地から開始する。旧JSONの開始番地も実験画面への読込時に0へ揃える。書込ミスでは旧ブロックの取得、キャッシュへの書込、RAMへの同じ値の書込、命令完了を分離する。途中ではキャッシュだけが新しくRAMが古い段階も表示するが、命令が完了するまで次の命令は実行しない。

「前へ」は `Machine.back()` で直前の1動作へ戻る。自動実行は停止する。CPU・実行RAM・キャッシュ内容・LRUと初回参照の履歴・アクセス記録・仮想時間・命令数を復元し、再び「次へ」を押すと同じ結果へ進む。終了・エラーからも戻れる。ジェネレータ自体は複製せず、命令境界のスナップショットから対象動作まで決定的に再実行して新しいMachineを作る。スナップショットは直近64命令境界に制限するが、それ以前は初期状態から再構築できるため、戻れる範囲は制限しない。

各動作で、命令・データの対象番地、または次に実行する番地がRAMの表示領域に入るよう自動スクロールする。ページの画面外にある場合も対象行が見える位置へ移動する。キャッシュヒット時も参照先のRAM行を表示するが、これは位置の確認であり、RAMアクセス・転送や待ち時間を増やさない。対象と次の命令は青、実行中の命令は緑、実際のRAM読出元は赤、書込先は緑で行全体の背景を塗る。矢印は現在の1つの転送を表示し、受取先の実際の命令欄・受信値欄・キャッシュセル・RAMの現在値セルの内側へ着地。大きい矢印先端、着点の輪、受取欄の枠を付ける。

比較などに使う `Machine.step()` は、同じ段階実行ジェネレータを命令完了まで進める。段階数で仮想時間を水増しせず、キャッシュ判定・ブロック取得・RAM書込の発生時に待ち時間を加算し、命令完了時にCPU時間を1回だけ加算する。命令の途中で保存した比較結果には「命令の途中」を明示する。

読出ミスをRAM → キャッシュ → CPUと順に表示するのは教材用の直列化。実機ではブロック取得中に要求値を先にCPUへ返すこともある。ライトスルーの書込は同じCPUの書込要求をキャッシュと主記憶へ反映するもので、キャッシュ内の別の命令がRAMへ書き込んでいるわけではない。実機のバス・コントローラ・書込バッファ・並行処理は省略している。

## 構成と確認

`model.mjs` はDOMから独立した実行モデル、`presets.mjs` は初期RAM、`app.mjs` はUI。HTMLは `lab/tools/templates/cpu-memory.html` から共通シェルで生成。

```sh
node lab/tools/build-pages.mjs
node --test lab/cpu-memory/model.test.mjs lab/cpu-memory/documents.test.mjs lab/cpu-memory/phases.test.mjs
node lab/tools/build-pages.mjs --check
LAB_JSDOM_MODULE=/path/to/jsdom node lab/tools/test-cpu-memory-dom.mjs
LAB_JSDOM_MODULE=/path/to/jsdom node lab/tools/test-cpu-memory-fullscreen.mjs
LAB_JSDOM_MODULE=/path/to/jsdom node lab/tools/test-cpu-memory-documents.mjs
LAB_JSDOM_MODULE=/path/to/jsdom node lab/tools/test-cpu-memory-phases.mjs
```

モデル検証：5プリセット×各容量とOFFの一致、アクセス時間の手計算、LRU、ブロック取得、ライトアロケート・スルー、命令上書き、分岐、初期条件の再現、エラー、独立した単純インタプリタとのランダム比較（100プログラム）。DOM検証：編集・初期化・命令実行・アクセス履歴のスナップショット・一時停止・比較・復元・直接入力・保存・JSON不正入力。全画面検証：DOMと実行状態の保持、編集中・比較記録、Escape、フォーカスとinertの復元、ネイティブAPI成功／拒否／途中終了／素早い再切替、キーボード操作と自動実行の一時停止。保存・転送検証：名前付き保存の独立性、上書き・複製・削除、JSON往復と不正データ、保存失敗、転送の方向とフェーズ、プリセット・保存済みデータの読込確認、速度の変更・入力検証、全画面ツールバー操作。段階検証：CPU命令の取得と実行、RAM参照前のスクロール、受信値と計算値の分離、ヒット時のRAMアクセス非発生、書込の各段階、段階実行と命令単位実行の一致、矢印の着点、途中結果の保存。DOM検証は描画レイアウトや実ブラウザの代替ではない。
