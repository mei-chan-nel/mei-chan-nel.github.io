# CPUと記憶装置

RAMの初期内容を書き換え、1命令実行または連続実行でCPUとキャッシュを観察する教材。Labの「アルゴリズム」に登録。

- RAMは0〜31番地。命令と数値を自由に配置。計算中の値は初期値0の1個。
- 命令は値の設定・読み出し・加算・減算・書き込み・無条件分岐・0の場合の条件分岐・終了の8種類。加算・減算は指定番地を参照し、値の設定は即値を使う。
- Studioで使用している `selection` / `field`（`expression-editor.js`）と `openTapPad`（`tap-controls.js`）をそのまま再利用。日本語の選択・直接入力・画面上の数値入力に対応。
- 実行中のRAMは右列、編集する初期RAMは左列。編集や設定変更の確定時には初期RAMからCPU・キャッシュ・計測をリセット。比較記録は保持。
- 命令取得・データ読み出し・データ書き込みで1個の全相連キャッシュを共有。2番地固定のブロック、1・2・4・8・16個から容量を選択（初期2個）。全参照でLRU更新。
- 書込ミスはライトアロケート。書込は毎回RAMにも反映するライトスルー。命令を数値で上書きした場合もキャッシュとRAMは一致。
- ミス理由は初回と容量不足を区別。各命令のアクセスを選ぶと、そのアクセス直後のキャッシュのスナップショットと置換理由を表示。
- 時間はCPU処理、キャッシュ参照、RAM転送を個別設定。2番地のブロック取得は1転送とする。ヒット率はCPUからの論理アクセスに対する割合。RAM転送回数は取得・書込を別計上。
- 合計時間 = 命令数 × CPU処理時間 + メモリ待ち。ヒットはcache、読出ミスはcache+RAM、書込ヒットはcache+RAM、書込ミスはcache+RAM×2。OFFは各アクセスRAMのみ。表示速度は仮想時間と独立。
- 5種類のプリセット、同じ初期条件からのON/OFF一括比較、最大12件の結果保存・削除・条件復元、JSONによる初期RAMと設定の入出力。ブラウザ内に自動保存。
- 比較の条件番号は初期RAMと開始番地でグループ化。各記録には全設定・初期RAM・最終RAM・計測値を保存。途中の結果には「途中」を明示。
- 不正な番地・命令位置・非数値データ参照・整数の範囲超過を検知。連続実行は10,000命令ごとに停止、一括比較は10,000命令で終了しなければ記録せず理由を表示。

実機のパイプライン・先読み・転送の重なり・クロックやバス、補助記憶装置を省いた教材モデル。キャッシュの有無で最終計算結果が変わらないことを重視する。

## 構成と確認

`model.mjs` はDOMから独立した実行モデル、`presets.mjs` は初期RAM、`app.mjs` はUI。HTMLは `lab/tools/templates/cpu-memory.html` から共通シェルで生成。

```sh
node lab/tools/build-pages.mjs
node --test lab/cpu-memory/model.test.mjs
node lab/tools/build-pages.mjs --check
LAB_JSDOM_MODULE=/path/to/jsdom node lab/tools/test-cpu-memory-dom.mjs
```

モデル検証：5プリセット×各容量とOFFの一致、アクセス時間の手計算、LRU、ブロック取得、ライトアロケート・スルー、命令上書き、分岐、初期条件の再現、エラー、独立した単純インタプリタとのランダム比較（100プログラム）。DOM検証：編集・初期化・命令実行・アクセス履歴のスナップショット・一時停止・比較・復元・既存タップ入力・保存・JSON不正入力。DOM検証は描画レイアウトや実ブラウザの代替ではない。
