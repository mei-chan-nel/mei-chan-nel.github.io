第2問A　（配点15）

次の文章を読み，後の問い（問1〜3）に答えよ。

商店街で，架空のコード決済「DNC Pay」の導入を検討している。通信できる環境での残高払いを扱い，利用者の認証と通信の安全性は確保されているものとする。

図1の両方式とも，読み取るコードに購入金額は含まれず，結果はサーバから客と店へ通知される。POSレジは，登録した商品の種類と個数から代金を計算する。

方式Aでは，店を識別する紙のコードを店頭に掲示し，繰り返し使う。客はスマートフォンで読み，金額を入力して店員の確認を受け，支払いを操作する。支払要求は客の端末からサーバへ送られる。

方式Bでは，客がスマートフォンに決済用情報を表すバーコードを表示する。店はPOSレジに接続したスキャナで読み取る。POSレジは登録商品から計算した金額を使い，サーバへ要求を送る。

図1　二つの方式の機器と情報の流れ

問1次の文章中の空欄 ア・イ に入れるのに最も適当なものを，後の解答群のうちから一つずつ選べ。

図1の②では，方式Aの場合は ア。方式Bの場合は イ。

ア・イ の解答群

  1. ⓪客の端末が，客が入力した金額を用いて支払要求を送る
  2. ①客の端末が，POSレジが計算した金額を用いて支払要求を送る
  3. ②客の端末が，読み取ったコードに含まれる金額を用いて支払要求を送る
  4. ③店のPOSレジが，客が入力した金額を用いて支払要求を送る
  5. ④店のPOSレジが，POSレジが計算した金額を用いて支払要求を送る
  6. ⑤店のPOSレジが，読み取ったコードに含まれる金額を用いて支払要求を送る

問2方式A・Bの導入と運用について考える。

ａ　店側に必要な機能と，金額の誤りを比較した説明として最も適当なものを，次の⓪〜③のうちから一つ選べ。ウ

  1. ⓪方式Aは入力額を店員が確認する負担があるが，レジごとに異なるコードを置けば，POSレジの金額と自動で照合できる。
  2. ①方式Bは店に読取機能が必要だが，客のコードから金額を得られるので，POSレジとDNC Payを連携させる必要がない。
  3. ②方式Aは店の読取機能やPOSレジとの連携を必要としない。方式Bはそれらが必要だが，客が金額を手入力する際の誤りを減らせる。
  4. ③方式Bは読取機能やPOSレジとの連携が必要だが，金額を自動計算するので，商品の種類・個数の誤登録による誤りも防げる。

ｂ　店の端末とサーバの間だけで通信が途切れた。客の端末はサーバと通信でき，店の機器の電源と店内の接続は正常である。別の通信経路への切替は行わない。

図1の支払要求について最も適当なものを，次の⓪〜③のうちから一つ選べ。エ

  1. ⓪方式A・Bとも支払要求を送れるが，店は結果を受信できない。
  2. ①方式A・Bとも，店が結果を受信できないので支払要求を送れない。
  3. ②方式Aでは客が支払要求を送れるが，方式Bでは店から送れない。
  4. ③方式Bでは客のコードを使うので，店の要求も客の通信回線を通して送れる。

問3客の金額入力を省き，店にコードの読取機能を追加せずに済むよう，方式Aを改良した方式Cを考える。

図2　方式Cの機器と情報の流れ

図2の①で，POSレジは店番号と支払金額をサーバへ送る。サーバは重複しない請求番号を付け，店番号・金額と対応付けて保存する。②で，請求番号と，その請求を指定するQRコードを店へ返す。店はコードを画面に表示する。

客が③でコードを読むと，アプリは④でサーバから店名と金額を取得する。内容を確認した客が支払いを操作すると，⑤で請求番号を指定した支払要求を送る。サーバは支払いを処理し，⑥で請求番号と結果を店と客へ通知する。

コードには有効期限がある。同じ請求番号への支払要求が複数届いても，成立する支払いは一度だけであり，成立した支払いはコードの期限後も有効である。異なる番号への支払いは独立に処理される。コードの発行・情報の取得・支払要求・結果通知には，それぞれ通信が必要である。

ａ　方式AからCへの変更について，利点と必要な対応を説明したものとして最も適当なものを，次の⓪〜③のうちから一つ選べ。オ

  1. ⓪Cでは同額の別の会計にも同じ請求番号を使い回せるので，会計ごとにコードを作る回数を減らせる。
  2. ①Cでは客の金額入力と店員による入力額の確認を省けるが，POSレジとの連携と，会計ごとのコード表示が必要になる。
  3. ②CではPOSレジの計算額をサーバへ送るので，商品の種類や個数を誤って登録しても，サーバが金額を自動で修正できる。
  4. ③Cでは店側に読取機能を追加せずに済むので，POSレジとの連携も不要となり，Aと同じ紙のコードを使い続けられる。

ｂ　商品登録用の機器を除き，決済に使う機能だけを考える。方式BからCへ変更したとき，店側で必要となる機能の説明として最も適当なものを，次の⓪〜③のうちから一つ選べ。カ

  1. ⓪Cでは店の決済用スキャナが必要であり，客にコードを示す画面は不要になる。
  2. ①Cでは店の決済用スキャナは不要になるが，客にコードを示す画面が必要になる。
  3. ②Cでは店の決済用スキャナと，客にコードを示す画面の両方が必要になる。
  4. ③Cでは店の決済用スキャナも，客にコードを示す画面も不要になる。

ｃ　方式Cで，客の支払操作後，客の端末とPOSレジの両方に「通信エラー：結果を確認できません」と表示された。

通信復旧後の対応中，コードの有効期限は過ぎないものとする。店員がPOSレジから元の請求番号をサーバに照会すると，表1の状態が返る。照会によって支払いの受付が停止することはない。同じ番号のコードは再表示できる。

表1　照会で返される状態

状態意味
支払済み既に支払いが成立している。
受付可能未成立だが，今後成立する可能性がある。
未支払いで終了未成立で，以後もこの番号では成立しない。

二重払いを防ぎながらDNC Payで支払いを完了させるため，次の対応手順を作る。空欄キ・クに入れるのに最も適当なものを，後の解答群のうちから一つずつ選べ。

元の請求番号で照会し，「支払済み」なら会計に反映して終える。「受付可能」ならキ。「未支払いで終了」ならク。再操作後も支払結果を確認できない場合は，再操作に使ったコードの請求番号でサーバに照会する。

キ・ク の解答群

  1. ⓪店員は元のコードを再表示し，客はそのコードで再び支払操作をする
  2. ①店員は新しい請求番号のコードを表示し，客はそのコードで支払操作をする
  3. ②店員は元の請求を支払済みとして会計に反映し，客には再操作を求めない
  4. ③店員は新しい請求番号のコードを表示し，客は支払操作をせず待つ
