パケット

「パケット」とは

パケット（packet）とは、ネットワークでデータを送受信するときに用いる、データの小さなまとまりです。

インターネットでは、画像や動画、Webページなどのデータを送受信するとき、大きなデータを小さな単位に分けて送ることがあります。この小さな単位をパケットといいます。

パケットには、実際に送りたいデータだけでなく、宛先などの情報も付けられます。

パケットの仕組み

データを小さく分けて送る

例えば、「ABCDEF」というデータを送信する場合を考えます。

元のデータ：［ A B C D E F ］

これを次のように分割して送ります。

  • パケット1：［ A B ］
  • パケット2：［ C D ］
  • パケット3：［ E F ］

それぞれのパケットはネットワークを通じて送られ、受信側では必要に応じて元のデータに組み立て直されます。

データを小さく分けることで、複数の利用者が同じ通信回線を使いやすくなります。また、一部のデータが失われた場合に、その部分だけを送り直す仕組みも実現できます。

パケットの構造

パケットは、大きく分けると次の二つの部分から構成されます。

部分役割
ヘッダ宛先や送信元など、通信に必要な情報を記録する
データ部実際に送りたいデータを格納する

例えば、インターネットで使われるIPパケットには、次のような情報が含まれます。

［ ヘッダ ｜ データ部 ］

ヘッダには、送信元IPアドレスや宛先IPアドレスなどが記録されています。

ネットワーク機器は、この宛先IPアドレスなどを確認して、パケットを適切な方向へ転送します。

パケット交換方式とは

パケット交換方式とは、データをパケットに分けて送受信する通信方式です。

インターネットでは、このパケット交換方式が利用されています。

パケット交換方式の特徴

パケット交換方式の大きな特徴は、複数の利用者が通信回線を共有できることです。

AさんがWebページを閲覧し、Bさんが動画を視聴し、Cさんがメールを送信している場合を考えます。パケット交換方式では、それぞれの通信のパケットを同じ回線に流すことができます。

ある利用者がデータを送っていない間には、ほかの利用者が回線を使えるため、通信回線を効率よく利用しやすくなります。

また、ネットワークの障害などによって、パケットが通る経路を変更できる場合もあります。

ただし、通信が集中すると回線が混雑し、パケットの到着が遅れたり、失われたりすることもあります。

回線交換方式との違い

パケット交換方式と対比されるのが、回線交換方式です。

回線交換方式は、通信を始めるときに送信側と受信側の間の通信経路を確保し、通信が終わるまで使い続ける方式です。従来の電話網などで利用されてきました。

比較項目パケット交換方式回線交換方式
データの送り方小さなパケットに分けて送る確保した経路を使って送る
通信経路通信中に変わる場合がある通信中は確保した経路を使う
回線の共有複数の通信で共有しやすい確保した部分は原則として他の通信に使えない
主な特徴回線を効率よく利用しやすい通信に必要な資源を確保しやすい

パケット交換方式では、通信中に専用の経路を占有し続ける必要がないという点が重要です。

なお、パケット交換方式は、有線通信でも無線通信でも利用できます。

ルータとルーティング

ルータの役割

ルータ（router）とは、異なるネットワークを接続し、パケットを適切な転送先へ送る機器です。

例えば、家庭のパソコンからインターネット上のWebサーバへアクセスする場合、パケットは複数のルータを経由して送られることがあります。

パソコンA → ルータ1 → ルータ2 → サーバB

ルータは、パケットの宛先IPアドレスを確認し、次にどの機器へ転送すればよいかを判断します。

ルーティングとは

ルーティング（routing）とは、パケットを宛先へ届けるための経路を選ぶことです。

ルータは、経路表（ルーティングテーブル）と呼ばれる情報を使って、パケットの転送先を決めます。

AからBへ向かう経路が次のように二つあるとします。

  • 経路①：A → ルータ1 → ルータ2 → B
  • 経路②：A → ルータ1 → ルータ3 → B

ネットワークの状態や経路情報の変更によって、利用する経路が切り替わることがあります。

そのため、同じ送信元から送られたパケットでも、必ずしもすべて同じ経路を通るとは限りません。

パケットは必ず順番どおりに届くわけではない

パケットは、必ずしも送信した順番どおりに届くとは限りません。

例えば、送信側が次の順番でパケットを送ったとします。

送信：［1］［2］［3］［4］

途中でパケットが通る経路や通信にかかる時間が異なると、受信側では次のような順番になることもあります。

受信：［1］［3］［4］［2］

また、ネットワークの混雑などによって、パケットが途中で失われる場合もあります。

インターネットでは、パケットを宛先へ届けようとしますが、必ず届くことや、順番どおりに届くことまでは保証しません。

そこで、通信の目的に応じて、TCPやUDPといったプロトコルが利用されます。

TCPとUDPの違い

TCPとUDPは、どちらもインターネットでデータを送受信するために使われるプロトコルです。

ただし、通信の信頼性や速さに対する考え方が異なります。

TCP：正確にデータを届けることを重視

TCP（Transmission Control Protocol）は、データを正しい順序で、欠けることなく届けることを重視するプロトコルです。

TCPには、次のような仕組みがあります。

  • 順序の管理：データに順序を示す番号を付け、正しい順番に並べる。
  • 確認応答：受信側がデータを受け取ったことを送信側に知らせる。
  • 再送：届かなかったデータを送り直す。

次のようにデータを送った場合を考えます。

送信：［1］［2］［3］［4］

受信：［1］［欠落］［3］［4］

TCPでは、確認応答などを利用してデータの欠落を見つけ、必要なデータを再送します。

また、順序が入れ替わって届いた場合にも、正しい順序に並べてからアプリケーションに渡します。

これにより、ファイルのダウンロードなど、データが欠けたり順番が入れ替わったりすると困る通信に適しています。

ただし、確認応答や再送などの処理が必要になるため、その分だけ通信に時間がかかる場合があります。

UDP：処理の少なさや速さを重視

UDP（User Datagram Protocol）は、TCPのような到着確認や再送、順序の管理を基本的には行わないプロトコルです。

例えば、UDPで次のようにデータを送った場合を考えます。

送信：［1］［2］［3］［4］

受信：［1］［3］［4］

途中で［2］が失われても、UDP自身はそれを送り直しません。また、届いたデータの順序を自動的に並べ直すこともしません。

そのため、TCPよりも通信の制御が単純で、余分な処理を少なくできます。

例えば、オンラインゲームや音声通話などでは、古いデータを何度も送り直すよりも、新しいデータを素早く届けることが重要な場合があります。このような通信にはUDPが利用されることがあります。

ただし、UDPを使えば必ずTCPより速くなるわけではありません。また、UDPを利用するアプリケーションが独自に再送などの仕組みを設けることもあります。

TCPとUDPの比較

比較項目TCPUDP
データの到着確認ある基本的にない
届かなかったデータの再送行う基本的に行わない
データの順序管理行う基本的に行わない
特徴信頼性が高い通信の制御が単純
利用例ファイル転送など音声通話、オンラインゲームなど

TCP/IPの階層構造

インターネットでは、さまざまなプロトコルが役割を分担して通信を実現しています。

この役割分担を整理したものが、TCP/IPの階層モデルです。

階層主な役割代表的なプロトコル
アプリケーション層Web閲覧などのサービスに関する通信HTTP、DNS
トランスポート層データの送受信や信頼性の管理などTCP、UDP
インターネット層IPアドレスに基づいてパケットを配送するIP
ネットワークインタフェース層ネットワーク内でデータを転送するEthernet、Wi-Fi

ここでは、特に次の役割の違いを理解しておくことが重要です。

  • IP：パケットを宛先へ配送する。
  • TCP：データの欠落や順序の乱れに対応する。
  • UDP：到着確認や再送などを基本的に行わず、データを送る。

また、通信で送るデータのまとまりには、階層によって異なる呼び方があります。

例えば、TCPで扱うデータのまとまりを「セグメント」、IPで扱うものを「IPパケット」、Ethernetなどで扱うものを「フレーム」といいます。

基本的な考え方は共通しており、それぞれの階層で必要な情報を付けながらデータを送っています。

EXAMPLE

例題

パケット · EXAMPLEオリジナル問題

パケット交換方式として最も適切な説明はどれか。

  1. 0

    通信中は送受信者間の物理回線を占有し続ける方式。

  2. 1

    送信データを必ず一つの画像ファイルにする方式。

  3. 2

    データを小さなパケットに分け、ネットワークで順に転送する方式。

  4. 3

    全ての通信を一台の端末だけで処理する方式。

解答・解説を確認

正解2．データを小さなパケットに分け、ネットワークで順に転送する方式。

解説

パケット交換方式は、データを小さなパケットに分け、それぞれに宛先などの情報を付けてネットワーク上で転送する方式です。複数の通信が回線を共有でき、混雑や障害に応じて別の経路を選びやすくなります。一方、パケットに分けるだけで正しい順序や到着が保証されるわけではなく、再送や順序制御などはTCPなど別の仕組みが担います。
