アクセス制御

「アクセス制御」とは

アクセス制御とは、情報やシステム、部屋などに対して、「誰が、何に、どのような操作をしてよいか」を決め、許可されていない利用を防ぐ仕組みです。

例えば、学校の成績管理システムについて、

  • 生徒は自分の成績だけを閲覧できる
  • 教員は担当する生徒の成績を閲覧・入力できる
  • 管理者は利用者の登録や権限設定ができる

というように、利用者によってできることを変えるのがアクセス制御です。

アクセス制御の対象は電子データだけではありません。例えば、関係者だけが鍵を開けられるキャビネットに機密文書を保管することや、許可された社員だけが特定の部屋に入室できるようにすることもアクセス制御です。

認証と認可

アクセス制御を理解するときには、認証と認可を区別することが重要です。

認証（Authentication）は、アクセスしようとしている人が「誰なのか」を確認することです。

代表的な方法には、

  • IDとパスワード
  • ICカード
  • 指紋や顔などの生体認証
  • ワンタイムパスワード

などがあります。

一方、認可（Authorization）は、認証された利用者に対して、どの情報や機能を利用してよいかを判断することです。

例えば、

  1. IDとパスワードを入力する
  2. 正しい利用者であることを確認する
  3. その利用者が管理者か一般利用者かを調べる
  4. 管理者であれば管理画面へのアクセスを許可する

という処理では、1～2が認証、3～4が認可に当たります。

つまり、

認証：あなたは誰ですね。
認可：あなたはこれをしてよいですよ。

という違いです。

アクセス権

利用者ごとに「何をしてよいか」を具体的に設定したものをアクセス権といいます。

代表的なアクセス権には、

  • 読取り（閲覧）
  • 書込み
  • 変更
  • 削除
  • 実行

などがあります。

例えば、共有フォルダについて、

利用者閲覧変更削除
一般利用者○××
担当者○○×
管理者○○○

のように設定できます。

アクセス権を適切に設定すると、権限のない人による閲覧や変更、削除を防ぎやすくなります。

アクセス制御と機密性・完全性

情報セキュリティでは、特に次の三つが重要です。

  • 機密性：許可された人だけが情報を利用できる
  • 完全性：情報が勝手に変更・破壊されていない
  • 可用性：必要なときに情報やシステムを利用できる

アクセス制御は、特に機密性と完全性を守るために重要です。

例えば、部外秘ファイルを許可された人だけが閲覧できるようにすれば、情報漏えいを防ぎ、機密性を高められます。

また、書込みや削除ができる人を制限すれば、権限のない人による改ざんや削除を防ぎ、完全性を守ることにもつながります。

一方、アクセス権を設定しただけでは、

  • 大量の通信を送り付ける攻撃
  • 画面ののぞき見
  • 機器の物理的な故障
  • 通信途中での盗聴

などを直接防ぐことはできません。

アクセス制御が何を防げるのかを考えるときは、「権限のない利用を防ぐ仕組みか」という点に注目します。

最小権限の原則

アクセス権は、多く与えればよいわけではありません。

基本となるのが最小権限の原則です。

これは、

利用者には、業務に必要な範囲の権限だけを与える

という考え方です。

例えば、図書館システムを利用する全職員に図書データの削除権限を与える必要はありません。削除が必要な担当者だけに権限を与えればよいです。

また、

  • 必要な人だけに与える
  • 必要な操作だけを許可する
  • 必要な期間だけ有効にする
  • 異動・退職時には不要な権限を削除する

といった管理も重要です。

権限を必要以上に与えると、誤操作や内部不正が起きたときの被害が大きくなります。

管理者にもアクセス制御が必要

システム管理者は一般利用者より大きな権限を持っているため、管理者による内部不正にも注意する必要があります。

そのため、

  • 管理者ごとに個別のIDを使用する
  • 必要以上の権限を与えない
  • 管理者の操作をログに残す
  • 重要な作業を別の人が確認する

といった対策を行います。

複数人で一つの共通IDを使用すると、問題が発生したときに誰が操作したのか分からなくなるため、適切ではありません。

また、管理者本人だけが自分の操作ログを確認できる仕組みでは、内部不正の監視として不十分です。

重要な操作については、本人以外の人も確認できる仕組みを用意することが有効です。

アクセスログ

誰が、いつ、どの情報やシステムにアクセスしたかを記録したものをアクセスログといいます。

例えば、

  • 利用者ID
  • アクセスした日時
  • アクセス先
  • 行った操作
  • 成功したか拒否されたか

などを記録します。

アクセスログを残しておけば、不正アクセスなどが起こった場合に、後から状況を調査できます。

ただし、

アクセス制御＝不正な操作を制限する仕組み
ログ＝行われた操作を記録する仕組み

であり、役割は異なります。

両方を組み合わせることが重要です。

入退室管理もアクセス制御

アクセス制御はコンピュータ上だけで行われるものではありません。

例えば、生体認証によって、

「この社員はサーバ室に入室できる」
「この社員は入室できない」

と判断する仕組みもアクセス制御です。

さらに、入室を試みた時刻や許可・拒否の結果を記録すれば、アクセスログとして利用できます。

ただし、入室だけを記録して退室を記録していない場合、

  • いつ退室したか
  • 何時間滞在したか
  • 現在何人いるか

などは分かりません。

システムで何が分かるかは、実際に何を記録しているかを確認して判断する必要があります。

紙の文書でもアクセス制御を行う

アクセス制御は電子ファイルだけを対象にするものではありません。

例えば、関係者外秘の紙文書であれば、

  • 関係者だけが開けられる施錠キャビネットに保管する
  • 鍵を持つ人を必要な人に限定する

といった方法でアクセスを制限できます。

また、不要になった機密文書をそのままごみに捨てると情報漏えいにつながるため、シュレッダーなどで復元しにくい状態にして廃棄することも重要です。

つまり、情報は、

利用中だけでなく、保管から廃棄まで適切に管理する必要があります。

ファイアウォールによるアクセス制御

アクセス制御は、利用者だけでなくネットワーク通信に対しても行われます。

代表的な仕組みがファイアウォールです。

ファイアウォールは、あらかじめ設定された通信規則に基づいて、

通信を許可するか、遮断するか

を判断します。

判断材料として、

  • 送信元IPアドレス
  • 宛先IPアドレス
  • ポート番号
  • 通信の種類
  • 通信の状態

などが使われます。

例えば、学校のWebサーバについて、

  • インターネットからWebページを見る通信 → 許可
  • インターネットから管理画面を操作する通信 → 拒否
  • 校内LANから管理画面を操作する通信 → 許可

という設定ができます。

このように、必要な通信だけを許可し、不要な通信を遮断することによって、不正アクセスの危険を減らします。

ファイアウォールで何でも防げるわけではない

ファイアウォールは重要なアクセス制御の仕組みですが、すべての攻撃を防げるわけではありません。

例えば、

  • 許可された通信を悪用する攻撃
  • USBメモリなどから持ち込まれたマルウェア
  • 利用者をだましてパスワードを入力させるフィッシング
  • 利用者自身による内部不正

などは、ファイアウォールだけでは十分に防げません。

そのため、

  • 認証
  • アクセス権
  • マルウェア対策
  • ソフトウェアの更新
  • ログ監視

など、複数の対策を組み合わせる必要があります。

Webフィルタリング

Webサイトへのアクセスを制限するWebフィルタリングもアクセス制御の一種です。

代表的な方法には、ブラックリスト方式とホワイトリスト方式があります。

ブラックリスト方式

禁止するサイトを登録し、それ以外は原則として許可する方式です。

例えば、

  • 危険なサイト
  • 不適切なサイト

をブラックリストに登録して遮断します。

利点は、登録されていないサイトを広く利用できることです。

一方、新しく作られた危険なサイトなどがまだ登録されていなければ、アクセスできてしまう可能性があります。

ホワイトリスト方式

許可するサイトを登録し、それ以外は原則として遮断する方式です。

未確認のサイトにはアクセスできないため、強くアクセスを制限できます。

その一方で、新しく見つけた有益なサイトでも、リストに追加されるまでは利用できません。

まとめると、

ブラックリスト：禁止したもの以外は許可
ホワイトリスト：許可したもの以外は禁止

です。

データベースとアクセス制御

データベース管理システム（DBMS）にもアクセス制御の機能があります。

例えば学校のデータベースなら、

  • 生徒：自分の情報を閲覧
  • 教員：担当する生徒の情報を閲覧・更新
  • 管理者：利用者やアクセス権を管理

というように、利用者や役割ごとに権限を設定できます。

DBMSを使うことで、データを一元的に管理するとともに、

  • 誰が閲覧できるか
  • 誰が変更できるか
  • 誰が削除できるか

などを管理しやすくなります。

組織外へ情報を共有するときのアクセス制御

機密性のあるデータを組織外の人と共有するときにも、アクセス制御が重要です。

例えば共同研究者一人だけとデータを共有したい場合には、

  • 相手を認証する
  • その人だけにアクセスを許可する
  • 閲覧だけ、編集可など権限を決める
  • 有効期限を設定する
  • アクセス記録を残す

といった方法を組み合わせます。

つまり、

誰が・何を・どこまで・いつまで利用できるか

を明確にすることが重要です。

誰でも利用できる公開URLに機密情報を置く方法では、適切なアクセス制御ができません。

アクセス制御と他のセキュリティ対策の違い

問題では、アクセス制御とは異なる対策が選択肢に混ぜられることが多くあります。

対策主な目的
認証利用者が誰かを確認する
アクセス制御・認可何を利用してよいかを制限する
暗号化内容を第三者に読まれにくくする
デジタル署名作成者や改ざんの有無を確認する
バックアップ消失・破損したデータを復元する
ファイアウォール通信を規則に基づいて許可・遮断する
ログ操作の記録を残し、後から追跡する

例えば、

「権限のない人にファイルを読ませたくない」

なら、アクセス制御が適しています。

「通信途中で内容を盗み見られたくない」

なら、暗号化が必要です。

「ファイルが改ざんされていないことを確認したい」

なら、デジタル署名などが利用できます。

「ファイルが消えたときに元に戻したい」

なら、バックアップが必要です。

問題文で何を防ぎたいのかを確認して対策を選ぶことが重要です。

例題

アクセス制御 · EXAMPLEITパスポートH26春期 問76（改題）

適切なアクセス権を設定することで効果がある対策だけを選んだ組合せはどれか。a: 大量の通信による攻撃を防ぐ。b: 情報漏えいを防ぐ。c: 画面をのぞき見されることを防ぐ。d: 権限のない人による改ざんを防ぐ。

  1. 0

    a、b

  2. 1

    a、c

  3. 2

    b、d

  4. 3

    c、d

解答・解説を確認

正解2．b、d

解説

アクセス権は、誰がどの情報を読んだり書き換えたりできるかを制御します。したがって情報漏えいや権限のない改ざんを防ぐ効果があります。
