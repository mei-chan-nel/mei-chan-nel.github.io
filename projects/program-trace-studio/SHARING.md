# Studio 共有URLの仕様

2026年10月4日策定。新しく生成する共有URLは **v2**、既存の **v1** は引き続き読み込みます。名前付き保存・JSONファイルの形式はv1のまま維持し、共有専用の形式を分離します。

## URLと入口

```text
https://mei-chan-nel.com/program-trace/studio/share.html#v2.d.<データ>
https://mei-chan-nel.com/program-trace/studio/share.html#v2.j.<データ>
```

- `d`：UTF-8のJSONをzlib形式のDEFLATEで圧縮し、パディングなしのBase64urlに変換。ブラウザの [Compression Streams API](https://developer.mozilla.org/en-US/docs/Web/API/CompressionStream/CompressionStream) を使います。
- `j`：同じJSONのUTF-8バイト列を、圧縮せずBase64urlに変換。
- Base64urlの文字は `A–Z a–z 0–9 - _` のみ。末尾の `=` は省略。復元時には未使用ビットも含めて正規形と一致することを確認します。
- JSONの前後に空白を付けず、オブジェクトの項目名を使わない配列形式にします。
- 候補ごとに実際のバイト数を測り、圧縮・非圧縮を比較します。完成したプログラムでは本文と命令の省略形式も比較し、最短のURLを採用します。
- 圧縮APIがない場合も、上限に収まる `j` 形式で共有できます。圧縮済みのURLを読めない場合はファイルによる代替を案内します。
- 共有本文はフラグメント内にだけ保存します。クエリは付けず、外部保存サービスや短縮URLサービスを使いません。

圧縮形式を変える場合は方式記号を、データの解釈を変える場合はバージョンを増やします。未知の方式・バージョンを別の形式として推測して読み込みません。

## 含める情報

共有するのはプログラム名、プログラム本文・行構造、配列の番号の開始値、外部入力の種類・範囲です。実行途中の変数・出力・入力済みの値・乱数の状態・Undo履歴・保存ID・行ID・式の列位置は含めません。

共有先では実行前の画面を開き、自動ではステップを進めません。「プログラムを編集」で編集画面に切り替えられます。作成途中の場合は空白行や空の入れ子も復元し、編集画面を表示します。受信しただけでは受信者の下書きを上書きしません。編集・保存した場合は共有フラグメントを消し、通常のStudio入口に戻します。

## 文書の配列

```text
[名前, プログラム]
[名前, プログラム, 配列の開始番号]
[名前, プログラム, 配列の開始番号, 外部入力の設定一覧]
```

開始番号の既定値は0、外部入力の既定値は空です。外部入力を指定する場合は、開始番号が0でも3番目を明示します。名前は通常の保存形式と同じく120文字までです。

`プログラム` は本文の文字列、または下記の命令の配列です。命令を使うときは本文・行番号・字下げ・「｜」「⎿」を復元時に再生成します。本文を省略形式から完全に再現できない場合は、元の本文の文字列を保持します。表記・コメント・空白を、短縮のために勝手に書き換えません。

作成途中の入れ子は本文だけでは復元できないため、命令の配列を使います。行IDは読み込みごとに新しく作ります。完成後は通常の本文に戻せるので、保存用の `builder` 情報を重ねて共有しません。

## 命令の番号

次の番号・引数順はv2の固定仕様です。`式`、`左辺` は後述の形式、`内側` は命令の配列です。

| 番号 | 処理 | 形式 |
|---|---|---|
| 0 | 空白行 | `[0]` |
| 1 | 代入 | `[1, 左辺, 式, 左辺, 式, …]` |
| 2 | 表示 | `[2, 式, 式, …]`。引数0個も可 |
| 3 | 外部入力 | `[3, 変数名]` |
| 4 | 条件分岐 | `[4, 条件式, 内側]` または `[4, 条件式, 内側, 次の分岐]` |
| 5 | そうでなければ | `[5, 内側]`。条件分岐の「次の分岐」にだけ置く |
| 6 | 範囲の繰り返し | `[6, 変数名, 開始式, 終了式, 内側]` または最後に `[増減する式, 方向]` を追加 |
| 7 | 条件の繰り返し | `[7, 条件式, 内側]` |
| 8 | コメント行 | `[8, コメント本文]` |

「そうでなくもし」は次の分岐に番号4を置きます。繰り返しの増減する値が1・方向が増加の場合は省略し、それ以外は `[増減する式, 1]` または `[増減する式, -1]` を追加します。

行末のコメントがある場合は、命令の最後に `{"c":"コメント本文"}` を付けます。空白行のコメントは付けません。行IDやオブジェクトの命令名は送信しません。

左辺は変数なら名前の文字列、配列の要素なら `[名前, 添字の式]` または `[名前, 行の式, 列の式]` です。

## 式の番号

数値・文字列・真偽値のリテラルはJSONの値をそのまま使います。文字列は式の本文として解釈せず、文字列リテラルとして扱います。

| 番号 | 式 | 形式 |
|---|---|---|
| 0 | 変数 | `[0, 名前]` |
| 1 | 配列 | `[1, 要素の式, …]`。二次元では要素に番号1の配列を置く |
| 2 | 要素参照 | `[2, 対象の式, 添字の式]` または添字の式を2個 |
| 3 | 単項演算 | `[3, 演算子番号, 式]` |
| 4 | 二項演算 | `[4, 演算子番号, 左の式, 右の式]` |
| 5 | 組み込み関数 | `[5, 関数番号または名前, 引数の式, …]` |

単項演算子は番号0から `+ - not` の順です。二項演算子は番号0から `+ - * / ÷ % ** == != < <= > >= and or` の順です。順序を変更しません。

関数番号0は `要素数`、1は `乱数` です。将来追加される組み込み関数は名前の文字列でも表せます。受信側の関数レジストリに登録されているものだけを受け付け、未知の関数をJavaScriptとして実行しません。`表示する` は式には入れず、命令番号2を使います。

合計のプログラムは次のようになります。

```json
["2つの値の合計", [
  [1, "x", 3],
  [1, "y", 4],
  [1, "goukei", [4, 0, [0, "x"], [0, "y"]]],
  [2, "合計は", [0, "goukei"], "です。"]
]]
```

## 外部入力の設定

各入力を `[名前, 変更項目のビットマスク, 変更した値, …]` にします。項目番号は次の順で固定し、変更した値を項目番号の小さい順に並べます。入力一覧も変数名の文字コード順に並べ、省略データの並びを一定にします。圧縮環境によって圧縮結果や採用方式が変わる場合も、復元されるプログラムと設定は同じです。

| ビット | 項目 | 既定値 | 値の形式 |
|---|---|---|---|
| 0 | kind | 0 | 0:number / 1:text / 2:array / 3:matrix |
| 1 | integer | 1 | 0:false / 1:true |
| 2 | min | -1000000 | 数値 |
| 3 | max | 1000000 | 数値 |
| 4 | minLength | 1 | 整数 |
| 5 | maxLength | 100 | 整数 |
| 6 | elementKind | 0 | 0:number / 1:text |
| 7 | rows | 2 | 整数 |
| 8 | columns | 3 | 整数 |

例えば整数の年齢を0～120で入力する設定は `["age", 12, 0, 120]` です。12はビット2と3を合わせた値です。既定値のままの入力でも `["変数名", 0]` を残します。省略した値は上の固定値から復元するため、将来UIの既定値を変えても過去のURLの意味を変えません。

使用中の入力種類に関係のない項目も、変更されていれば保持します。範囲や配列の大きさは通常の `validateInputSpec` で検証します。

## 互換性・検証・上限

- `#v1.<データ>` は従来どおりgzip→UTF-8→保存用JSONとして復元します。元の本文・設定・作成途中の行IDも保持します。
- 新形式はBase64urlの正規形、方式、UTF-8、JSONの形、命令・式の種類と引数数、入力設定、行数、深さを検証してから編集・実行のデータに変換します。
- 本文・設定・行データは既存のパーサー・検証関数を再利用し、`eval`・`Function`・任意のコード実行はしません。
- URL全体は100,000文字まで、復元した共有データは180,000バイトまでです。圧縮ストリームは上限を越えた時点で停止します。
- 本文は500行・50,000 UTF-8バイト、入れ子は32段、構造化された式は20,000個までです。ファイル・実行時の既存の上限も適用します。
- 欠けたURL、未知のバージョン、不正なデータ、上限超過では理由を表示し、URL全体の再送またはファイルによる代替を案内します。受信エラーで保存済みの下書きを置き換えません。

## 検索向けの扱い

共有先は常に `share.html` の1つの静的HTMLです。プログラムごとのHTMLやクエリ付きページを生成しません。HTMLにはJavaScriptを実行する前から `noindex, follow` を設定し、canonicalはフラグメントを含まない共有入口に固定します。共有入口・個別URLはXML/HTMLサイトマップに登録しません。

旧形式を通常のStudio入口のフラグメントとして開いた場合も、アプリ初期化時・hashchange時にrobotsを `noindex, follow` にし、canonicalを共有入口にそろえます。通常のStudio入口とプログラムトレースの一覧は引き続き検索対象にできます。

robots.txtで共有入口をブロックせず、検索エンジンがnoindexを読めるようにします。[Googleのnoindexの説明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)に沿った処理です。アクセス解析にもフラグメントを送りません。

## 計測

```powershell
npm.cmd run benchmark:shares
```

同じ本文・初期値・入力設定・本番URLで、v1のgzip JSONとv2の最短候補を比較します。代表例は再帰を除く14題を使用し、二次元配列はStudioの規則に合わせて初期配列を明示します。

2026年10月4日の計測では14題合計が **6,452文字→3,685文字（42.9％短縮）** でした。2つの値の合計は296→197文字、二分探索は767→442文字、作成途中の入れ子の例は783→168文字です。URLの長さにはドメインとパスも含めます。
