# プログラムトレース

共通テスト「情報Ⅰ」の表記で、用意されたプログラムを1行ずつ実行する学習ページです。
`mei-chan-nel.github.io` リポジトリの `program-trace/` に独立して実装しています。
実装・テスト・この説明書は、すべてポータル側で管理します。
共通ヘッダー・フッターとトップページから利用できます。
公開URLは `https://mei-chan-nel.com/program-trace/` です。
検索向けメタデータ・構造化データと、XML・HTMLのサイトマップを設定しています。
既存の問題データは変更していません。

## ローカル確認

ポータルのリポジトリルートで次を実行し、`http://127.0.0.1:8773/program-trace/` を開きます。

```powershell
python scripts/preview_site.py --host 127.0.0.1 --port 8773
```

ビルドや npm パッケージのインストールは不要です。ブラウザの ES Modules を使うため、
HTML のダブルクリックではなく HTTP サーバーから確認してください。
実行・入力・値の変更はブラウザ内で完結します。設定はページを開いている間だけ保持します。

ローカルサーバーは、ポータルを `/`、隣接する `info1-quiz-app` を `/info1-quiz-app/` で配信します。
アプリが別の場所にある場合は `--app-root <アプリのリポジトリルート>` を指定します。
このサーバーは静的ファイルの確認用で、クイズ用のローカル集計APIは提供しません。

直接表示・再読み込みでき、問題の追加時に個別HTMLやサーバーのルーティング設定を増やす必要がありません。

代表問題のIDとの重複を避けます。設定値や入力値・実行途中の状態はURLに含めません。

一覧の canonical は `https://mei-chan-nel.com/program-trace/`、robots設定は `index, follow` です。
実行画面のHTMLは `run.html` に分け、最初のHTTP応答から `noindex, follow` を指定しています。
実行入口の canonical は `/program-trace/run.html` に統一し、問題ID・遷移元を含めません。
XML・HTMLサイトマップには一覧だけを登録し、実行入口やその条件付きURLは登録しません。
`robots.txt` で実行入口を遮断せず、GoogleがHTMLのnoindex指定を読み取れるようにします。
`scripts/build_program_trace_pages.py` が代表15問のカードと、一覧と共通のHTMLから実行入口を生成し、統合検証で同期を確認します。
生成にはPythonとNode.js 22を使います。npmパッケージのインストールは不要で、生成済みHTMLをそのまま公開します。
Googleの仕様は [noindexによる索引制御](https://developers.google.com/search/docs/crawling-indexing/block-indexing) と
[JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) を参照してください。
共通ナビゲーションは他のページと同じ構成に揃えています。
公開時はポータルとアプリの統合検証を通して、両リポジトリの `main` へ反映します。
独自ドメインとGitHub Pagesの関係は [GitHub公式ドキュメント](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages) を参照してください。

## 共通ヘッダー・フッターと広告

ページは `assets/site.css` と `assets/site-header.js` を読み込み、ポータルと同じヘッダー・フッターを使います。
「プログラムトレース」は「講義ノート」の次です。静的HTMLと各ページの生成処理にもリンクを置き、
共通スクリプトは不足したリンクの補完と現在位置の表示を行います。
学習アプリのコンパクトなメニューとフッターにも同じリンクを補完します。
スマートフォンのナビゲーションも他のページと同じ横スクロールを使います。
共通スクリプトが計測するヘッダーの高さに、プログラム・変数欄の追従位置を合わせています。

本体の `</main>` の後、共通フッターの前にディスプレイ広告を1枠置きます。
既存の `assets/manual-ads.js` のディスプレイスロットを使い、ページ読込時に1回だけ初期化します。
一覧と実行画面の切り替え・次へ・最初からで広告を作り直したり、リクエストを繰り返したりしません。
未配信時は共通処理で枠を非表示にします。広告アカウントの設定やスロット番号は変更していません。

## 操作と表示

- 初期状態では行を選択しません。「次へ」でその行を実行し、緑背景の「実行中」と
  変数・出力・解説を同じステップにそろえます。最後の行の後も「次へ」を1回押せます。
  その操作で行の選択と解説を解除し、「次へ」を無効にします。最終値と出力は保持します。
  自動実行では最後の行を1間隔表示してから同じ終了状態へ進みます。
- 操作は「次へ」「最初から」「値を変更する」「自動実行」「実行速度」の順です。
  自動実行中は「一時停止」になり、速度は初期値0.5秒です。0.1秒以上は0.1秒刻みで変更できます。
  0.1秒から「−」を押すと0.01秒、さらに押すと0.001秒になります。「＋」で逆方向に戻せます。
  秒数の直接入力と上下の矢印キーにも対応します。実際の間隔はブラウザのタイマー処理に依存します。
  実行中の速度変更は次の待ち時間から反映し、速度変更だけでは行を進めません。
  停止・リセット・完了・例題変更後も速度を保持します。
- PCは左にプログラム、右に解説・変数・出力を縦に配置します。プログラムは行間を詰めて全行表示します。
  右側の高さは設定値・入力の許容範囲・出力行数・呼び出し数から実行前に計測し、実行中は固定します。
  枠内にスクロールバーを作らず、必要な場合はページ全体でスクロールします。PCではプログラムを追従表示します。
  例題の選択欄・変数欄の注釈・英語の装飾見出しは表示しません。例題一覧へのリンクから切り替えます。
  スマートフォンは縦に並べ、値の要約を上部に固定します。
- 「変数の値」で、代入元の変数・配列要素を薄い赤、代入先を緑で表示します。
  `tmp = x` は `tmp` が緑、`x` が薄い赤です。配列では実際に使った要素を色付けし、
  添字を計算する変数は代入元として色付けしません。条件判定や表示の後は代入元の色を解除します。
  代入元と先が同じ場合は緑を優先し、変更前の値を薄い赤で示します。プログラム内の変数名は通常の色です。
- 配列は0からの要素番号と値をマスで表示します。代入先は緑、代入元は薄い赤で、条件式などで参照した要素は青枠です。
  変更前後は `Data[0] 3 → 9` のように表示します。二次元配列は実際の添字を行・列見出しに使います。
  この九九の表は1からの添字です。まだ代入していないマスは `—` で表示します。
  長い配列は変更・参照している要素を含む最大40個を表示し、「全N要素を見る」で全体を確認できます。
- `表示する()` の出力を順に蓄積し、解説は「表示する」「『結果』と表示する。」の形式にします。
  配列は `[1, 2, 3]`、二次元配列は `[[1, 2], [2, 4]]` の形で表示します。
  小数は表示時だけ有効数字10桁に整え、計算には元の数値を使います。
  出力欄の表示上限は実行前に計測した件数、最大30件です。それを超えた場合は直近の出力を表示し、
  「すべての出力を見る」から最初の出力を含む履歴全体を確認できます。過去の出力データは削除しません。
  配列全体・出力履歴の確認ダイアログを開くと自動実行を停止します。
- for の先頭行でカウンタを初期化・増加して終了値以下か確認します。例6は `i = 6` の判定で終了します。
  while の先頭行は判定だけです。例11の初期設定は `sum = 21, i = 6` で終了します。
  else-if / else の行も、そこに進んだ場合は1ステップとして表示します。
- 関数は定義時に本体を実行せず、呼び出し時に各呼び出しの変数を用意します。
  再帰では呼び出しの一覧と、実行中の呼び出しの `n` を表示します。
  戻り値を返す行と、呼び出し元の計算を再開する行をそれぞれ追跡します。
  `factorial(5)` は `n = 0` に達してから `1, 1, 2, 6, 24, 120` を返し、最後に120を表示します。
- 乱数は0以上1未満です。1つの `乱数()` につき1回生成し、解説を作るために再生成しません。
  「最初から」では新しい乱数列を使います。テストでは乱数の初期状態を固定して検証できます。

## 外部入力と値の変更

【外部からの入力】の行では、実行時に専用ダイアログを開きます。
確定するまでステップ数や変数を更新しません。自動実行は入力中に停止し、確定した結果を
選択中の1間隔だけ表示してから再開します。キャンセル・Escape は入力前の状態を保持して停止します。
リセット後は外部入力を再度求めます。二分探索の配列と target は別々のダイアログです。

| 外部入力 | 許容値 |
| --- | --- |
| 年齢 age | 整数0〜120 |
| number | 整数−9999〜9999（0・負数も剰余で判定） |
| バブルソートの Array | 2〜12個、各要素は整数−999〜999 |
| 二分探索の Array | 1〜20個、各要素は整数−999〜999、昇順（同値可） |
| 二分探索の target | 整数−999〜999 |

「値を変更する」は途中の変数を直接書き換えません。設定を適用すると最初からになります。
配列は要素ごとに数値を入力し、「要素を追加する」と各要素の「×」で要素数を変更できます。
設定と外部入力のどちらでも同じ操作を使います。
要素の交換は最低3個、得点と最大値は最低1個です。得点は0〜100、配列は通常最大20個です。
空欄・小数・不正な要素数・範囲外は適用しません。二分探索では設定画面でも昇順を検証します。
外部入力の設定は実行時ダイアログの入力候補に反映し、確定を省略しません。
設定のキャンセル・Escape は元の値を保持し、自動実行は停止したままになります。

動画問題の入力条件は個別に定義しています。文字列のYes・Noや天気は選択式、ビットは0・1、
16進数は0〜9・A〜F、ISBNは12桁です。ユークリッドの互除法の除数は1以上にし、
二分探索・マージの配列は昇順を検証します。配列長を変更できる問題と、ISBNなど長さを固定する問題を区別しています。
二次元配列は行ごとの入力欄を使い、列の型・範囲を保持して行数を変更できます。

代表問題のforは500回以下、階乗は0〜10、乱数の試行回数は1〜1500です。
動画問題の上限は問題ごとに設定しています。実行回数は通常10,000ステップ、
Q324・Q330は20,000、Q326は100,000ステップまでです。関数の呼び出しは32段までです。

式を小さなスタックマシンで計算します。関数呼び出しでは計算を中断し、戻り値で再開します。
配列や呼び出しフレームを含め、`step()` は過去の状態を変更しません。
登録された表記だけを専用パーサーで命令データに変換し、ユーザーの自由なプログラムは受け付けません。
ユーザー入力は問題ごとの型・範囲・要素数に検証し、表示にはテキストノードを使います。
一覧カードのHTMLを作る場合も、データの文字列はエスケープして挿入します。

登録する問題は次のデータを持ちます。一覧・設定フォーム・変数欄はデータから生成します。

1. 一意な `id`、`number`、`title`、`category`、`accent`、`description`、`focus`。
2. `source`：行番号を除いた原文。変更可能な値は `{key}` で埋め込みます。
3. `program`：表記と同じ行番号を持つ命令データ。
4. `parameters`：`numberField()` または `arrayField()` で定義する変更可能な設定。
5. `inputs`：外部入力の条件。`input(line, name, field)` と同じ条件を使います。
6. 必要なら `validate(values)`、行番号の桁数 `lineNumberDigits`、二次元配列の表示範囲 `arrayShapes`。

命令は `assign`、`input`、`print`、`if`、`else`、`for`、`while`、`define`、`return`、`append`、`reverse`、`plot`。
`body` を入れ子にでき、if の `otherwise` に次の if または else を置きます。
式は値・変数・設定値・配列参照・要素数・関数呼び出し・乱数・四則演算・整数の商・剰余・累乗・比較です。
