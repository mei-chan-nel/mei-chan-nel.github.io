# Supabase 接続の公開前手順

現状: 統計取得のみ接続。送信は無効。DB・Edge Function・Turnstileは未設定／未デプロイ。安全性の実DB検証が済むまで有効化しない。

## 方式

`mock-exams/server/index.ts` は得点をブラウザから受け取らず、同梱した版固定の問題JSONと採点エンジンで再計算する。復習はクライアント側で送信対象から除外する（匿名ブラウザからの自己申告をサーバーだけで完全に証明することはできない）。

受験UUIDと256ビットの受験トークンを生成し、端末側に保存。DBはトークンのSHA-256だけを保持する。受験＋リビジョン単位で冪等に置換。古いスナップショットの集計を引き、新しい採点結果を加える処理を単一トランザクション内で実施。同じリビジョンの異なる内容は拒否し、古いリビジョンは無視する。完全未回答はスナップショットから除外。

TurnstileとIPごとの時間枠制限を併用。正当な再受験は別UUIDとして集計。匿名利用のため、すべての意図的な虚偽回答を排除する仕組みではない。

## 必須の残作業

1. 現在の `mock_exam_stats` のDDL・既存RPC定義を確認し、ステージングでSQL migrationを適用。既存学習アプリのテーブル・RPCは変更しない。
2. 配布するEdge Function内に採点エンジンと承認済みのexam.jsonを同梱する。`MOCK_EXAM_ALLOWED_ORIGIN`、`MOCK_EXAM_TURNSTILE_SECRET`、`MOCK_EXAM_IP_SALT` とSupabase標準サーバー環境変数を設定。
3. EdgeゲートウェイでIPヘッダーが利用者に偽装されないことを確認する。信頼済みIPヘッダーがない構成では公開しない。
4. フロントにTurnstile公開キー、受験トークン生成、最新リビジョンの永続outboxを実装。成功確認までoutboxを消さず、再送は同じリビジョン・同じ内容。先行リビジョンが未送信なら最新スナップショットへ置換する。Aの中断・復習ではoutboxに追加しない。
5. 同時初回送信、重複送信、逆順到着、採点変更、未回答へ変更、別トークンによる上書き、複数受験並行更新を実DBで検証する。
6. 定期タスクで古いrate-limit行を削除する。スナップショットは冪等性の根拠なので保持期間を決めるまで削除しない。
7. 以上を確認してから `statsConfig.submitUrl` を設定し、未接続表示を外す。

Service-roleやSecret keyを静的サイトに追加しない。SQLは管理者用の実行ファイルであり、クライアントが自由な得点を送るためのRPC公開権限は設けない。

追記: フロントの `engine/outbox.mjs` にスナップショット置換・失敗時保持・同revision再送を実装。採点結果画面に設定済みの場合のみTurnstileを起動する接続処理を追加済み。`statsConfig.submitUrl` と `turnstileSiteKey` はnullのまま。手順4の実装をゼロからやり直す必要はないが、実Endpointで検証すること。

## ローカルDB検証（2026-10-27）

外部ネットワークのない一時PostgreSQL 17に、仕様記載のmock_exam_stats相当テーブルとSQLを作成して検証済み。テストは `mock-exams/tests/sql_integration.py`。本番のDDLを取得した検証ではない。

- 同revision再送で件数が増えない。
- 再採点で旧回答キー・得点を除き、新結果へ置換。
- 古いrevision・同revision異内容・別トークンを適切に拒否／無視。
- 未回答へ戻した採点単位を集計から除く。
- 16受験の重複を含む32並行送信を16件だけ集計。
- 同じ受験の10revisionを逆順・並行送信して最新へ収束。
- anon/authenticatedは更新RPCを実行不可、service_roleのみ実行可能。
- 時間枠内120リクエストを上限に抑制。

一時コンテナは検証後に削除済み。本番の権限・現在のDDL、Edge Functionからの呼出し、Turnstile、信頼済みIPヘッダーは引き続き要検証。
