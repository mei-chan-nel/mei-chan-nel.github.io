入口: `/mock-exams/`。静的配信のみで受験・採点・ローカル履歴・復習・PDF閲覧が動作する。既存学習アプリのソース・ストレージキー・Supabase RPCは変更していない。

## ファイル構成

- `mock-exams/index.html`, `app.mjs`, `app.css`: 一覧、受験、結果、履歴、復習の共通画面。
- `mock-exams/booklet.css`: PC・モバイル・印刷の教材表示補正。
- `mock-exams/engine/`: 共通採点、受験状態、ローカル保存、統計取得、採点単位ごとの送信状態管理。
- `mock-exams/catalog.json`: 現行模試一覧（表示時は番号の降順）。
- `mock-exams/exams/<番号>/<版>/exam.json`: 解答欄・採点単位・教材の定義。
- 同階層の `q1.html` など: 原稿を保持し解答バインディングを追加した教材。iframeで元のCSSを隔離する。原稿のscriptとイベント属性は除去する。
- `source/`: 改変しない入力原稿。教材側はnoindex。原稿を公開対象から除外したい場合はホスティング設定側で除外可能。
- `problem.pdf`, `solution.pdf`: 端末によらず同じA4冊子。
- `mock-exams/connection-check.html`: テスト用模試IDによるRPC接続確認。接続契約はSUPABASE-DIRECT-RPC.md。

## データと描画の分離

HTMLを固定のテンプレートへ再入力せず、原稿ごとのアダプターが次の共通属性を付ける。CSSクラス、表組み、SVG、図、プログラムの構造は教材ごとに異なってよい。新しい原稿で変更するのは教材の変換処理とexam.jsonのみ。

| 属性 | 意味 |
|---|---|
| `data-field="q1-ア"` | 共通解答欄ID。複数箇所に同じIDを置くと同期する |
| `data-original="ア"` | 未回答時に表示する記号 |
| `data-display="content"` | 番号の代わりに選択した式や命令を埋める |
| `data-part="0"` | 選択肢の `parts` の該当部分を表示。No.001の第4問A/Bで使用 |
| `data-choice-fields="q2a-イ q2a-ウ"` | 選択肢を共有する解答欄。対象が不明なときは欄を選ぶ |
| `data-choice-value="1"` | クリック時の回答値 |

選択肢の短い内容は番号＋内容、長い内容は番号だけで欄に表示する。選択肢本文は原稿のまま選択でき、ポップアップにも内容を表示する。

### exam.json

`schemaVersion:1`、`id`、正の整数の`version`（初期値1）、`durationSeconds`、`maxPoints`、`sections`、`fields`、`scoring` が必須。

`fields` は `id, sectionId, label, type` を持つ。choiceは `choices:[{value,text,parts?}]`、textは `allowed` と `maxLength` を指定。0〜9/A〜Fの4×4キーパッドは許可文字以外を無効にする。物理キー、削除、クリア、次の欄も利用可能。

`scoring` は `id,sectionId,fields,maxPoints,rule` を持つ。fieldsの順序が統計の回答キーの順序となる。

```json
{
  "id": "q2a-02", "sectionId": "q2a", "fields": ["q2a-イ", "q2a-ウ"], "maxPoints": 3,
  "rule": {"kind": "unordered", "patterns": [["1", "5"]]}
}
```

採点規則:

- `exact`: patternsのどれかと順序を含めて一致すれば満点（単一・順序指定完答・複数正答）。
- `unordered`: 重複を含む多重集合として一致すれば満点。同じ番号の重複を勝手に除かない。
- `unordered-partial`: patternsと一致した要素数に応じ `pointsByMatches:[0,1,3]` の点を与える。
- `cases`: `cases:[{answers:[...],points:1,unordered:false,when?:...}]` を先頭から照合。特定誤答への部分点など。
- `conditional`: `when` に応じ `then` / `else` の採点規則を適用。
- 条件は `field/equals`、先行採点単位の `unit/atLeast`、`all:[...]`、`any:[...]`。依存先の採点単位は先に並べる。任意コードやevalは使わない。

## 保存と時間

既存アプリとは別の `study-atlas:mock-exams:v1:attempt:<UUID>` を使用。同じ保存内容を通常キーとbackupキーに書き込み、読み戻して確認する。送信状態は両方からマージして過去へ戻さない。保存失敗は画面で通知する。履歴のファイル書き出し・読み込みは提供しない。Web Locks対応ブラウザでは同じ受験の別タブ同時編集を拒否する。非対応ブラウザでは同時編集をしないよう明示する。

経過時間は開始タイムスタンプと累計で管理。明示的な中断で時計を停止。受験中に閉じた場合は次の再開まで時間が進む（60分モードの抜け道を作らない）。制限時間後は自動採点。同じ受験を時間制限なしへ切り替えて続けることもできる。

採点ごとにローカルのrevisionを増やす（RPCには送信しない）。復習は採点時のgradedAnswersとresultから凍結したスナップショットを作り、回答変更・再採点は行わない。古い保存データのreview領域は互換読み取りだけを維持し、画面では使用しない。端末内の保存データは型・値を検証して復元する。

## 模試トップの2つの入口（2026-10-28）

- 回ごと：一覧で60分／時間制限なし → 模試No.選択で全大問を直接開始。
- 大問ごと：第1問／第2問A／第2問B／第3問／第4問 → 模試No. → 選んだ大問だけ開始。同じNo.は同じ問題データを使う。
- 中間の詳細画面は設けない。各No.の右側に「問題冊子PDF」「解答解説PDF」の同一オリジンのダウンロードリンクを置く（download属性、別タブ指定なし）。大問別でもPDFはそのNo.の全大問。履歴・復習は両方式共通。
- 未受験・中断中・採点済みは、現行の問題版について通し／各大問を分けて判定。時間あり／なしは通し受験の同じ範囲に含める。未完了の履歴があれば再開を優先し、「最初から解く」で新しい受験も開始できる。再開は保存済みの時間条件を維持し、新しい受験は一覧で選んだ条件を使う。削除済み履歴は除外。
- おすすめ順は未受験→中断中→採点済み、同じ状況では新しい順。新しい順は公開日があれば日付、同日の場合や日付未指定では番号降順。番号順は昇順。

## 採点・履歴画面の整理（2026-10-28）

トップの「学習履歴」ボタンから `#history` の専用画面を開く。受験日時、模試No.、方式・大問、状態、得点、得点率、解答時間を一覧でき、すべて／回ごと／大問ごとで絞る。採点結果、復習、再開、削除をここに集約。操作は4列の固定位置へ揃え、利用できない操作は「—」とする。履歴の書き出し・読み込みは撤去。結果の「一覧に戻る」は模試一覧へ、「学習履歴に戻る」は履歴へ戻る。

通常の採点と時間切れは `gradingKind="final"` として終了し、結果画面に「解答に戻る」は出さない。「ここまでを採点して中断」だけ `interim` として保存し、結果の「解答を再開」と一覧の「中断中」を維持する。過去の保存データに値がない場合は通常採点として扱うが、paused/activeの履歴は再開できる。復習は学習履歴の「復習」から開始し、元の成績と送信状態に触れない。

結果の大きな合計得点と得点率・時間の重複表示を削除。破棄ボタンは「一覧に戻る」の右で集計表の右端に揃える。過去成績ボタンは解答表の右端に揃え、履歴列の展開時は表の表示領域の右端を上限とする。表本体だけを横スクロールさせる。

受験・復習・解説の画面はグローバルヘッダーとプレビュー告知を隠す。「一覧に戻る」は大問ナビと同じ行、右メニューは問題の白い紙面の上端に揃え、PCではstickyを維持する。画面表示の最初の紙面だけ上余白をなくし、印刷用の組版は変えない。

Sitesのビルドだけに `mock-exams-preview-samples` メタを付け、端末内にNo.001のサンプル6件（通し3、大問別2、途中採点1）を追加する。既存履歴を上書きせず、削除済みサンプルを復元しない。各行に「サンプル」を表示する。通常版には追加しない。`isSample`を保存・復元・backup統合で保持し、サンプルは回答変更・再開・採点・履歴読込み後も集計RPCへ送信しない。削除は履歴画面で通常の履歴と同様に行える。


## 閲覧専用の復習と画面復帰（2026-10-28）

復習は本人の採点時の回答・○✕△・未回答を問題上に表示する。正解は緑、不正解は赤、部分点は黄、完全未回答は灰色。`createReviewSnapshot`は回答と結果を複製して再帰的にfreezeし、編集中の未採点回答があっても混ぜない。入力イベント・キーパッド・採点・中断・時計は付けない。読み返しによる端末の回答・得点・時間の更新や統計記録はない。通常の再開では回答を編集でき、復習とは区別する。

画面状態はHistory APIと同じタブのsessionStorageへ保存。履歴の絞り込み・縦横スクロール、大問、履歴列の開閉、復習／解説の戻り先を引き継ぐ。解説は採点結果から開けば結果へ、復習から開けば元の大問の復習へ戻る。結果・復習・再開から学習履歴へ戻れ、ブラウザの戻る／進む・再読み込みも処理する。最終採点時は編集画面の履歴エントリーを結果へ置き換え、戻る操作で終了済み受験を編集し直さない。

統計記録は`doGrade`から明示的に呼ぶときだけ実行する。保存済み結果・復習・解説を閲覧するだけでは記録しない。統計取得はこれまでどおり結果を表示するときに行う。

`browser-navigation.cjs`で4種類の背景色、採点時回答の固定、結果・復習・解説・履歴の復帰、フィルターと横スクロール、ブラウザの戻る／進むと再読み込み、閲覧時の記録0件を検証する。部分点用の問題変更はブラウザのテスト応答だけであり、配信するNo.001は変更しない。


## 大問別成績と表の列操作（2026-10-28）

`engine/history-grid.mjs`は履歴の表示行、成績の切り出し、列の並び替え・絞り込みを担当する。`ui/history-grid.mjs`は全表示で共通の列メニューと表を描画する。追加のDBオブジェクトや通信はない。

- 「すべて」は受験1回を1行のまま表示。「回ごと」は通し受験だけを1回1行で表示。
- 「大問ごと」は、通し受験をq1/q2a/q2b/q3/q4へ分け、元から大問別で取り組んだ受験と併記する。「回ごと・60分」「回ごと・時間制限なし」と時間条件を表示し、点数・満点・得点率はその大問の保存済み成績を参照する。
- 切り出しは表示上の行だけ。UUID、元の受験のsectionIds、回答、採点結果、送信状態は変更・複製しない。採点結果・復習・解説は選んだ大問に絞って開ける。
- 切り出し行の再開は、元の通し受験を選んだ大問から開く。全大問の受験であることと時間条件を維持し、その後の採点も通し受験全体を対象にする。
- 通し受験の大問別時間は記録していないため切り出し行では「—」。総時間を大問の時間として流用・按分しない。
- 切り出し行またはその結果から削除するときは、元の通し受験全体が消えることを画面で確認する。大問だけの削除・統計取り消しは行わない。

各列見出しの▾から昇順／降順、検索とチェックボックスによる値の選択ができる。日付には日付範囲、得点・得点率・解答時間には数値範囲を用意（時間の入力単位は秒）。複数列の条件はANDで結合。空欄と0点は区別し、数値は数値、No.は数字の順で並べる。日付範囲は利用者のブラウザの暦日で比較する。

操作は3表示で共通。表示条件は各タブごとに保持し、結果・復習からの復帰と再読み込みでも復元する。列ごとの解除、条件チップでの解除、表示条件のリセットを用意。サンプル6件では「すべて」6行／「回ごと」3行／「大問ごと」18行になる。

検証：history-grid.test.mjs、browser-grid.cjs。表示上の切り出しと原本不変、0点と未採点、列操作の組み合わせ・範囲境界、復帰・再読み込み、スマホのメニューと横スクロール、削除の範囲確認、通し受験としての再開・採点を確認する。browser-history.cjsとbrowser-navigation.cjsでも既存動作を確認する。統計通信は模擬。

`ui/paired-reading.mjs`は2つの文書を表示後、各対応箇所の上端を測り、早く始まる側へ必要な高さの余白を置く。ウィンドウ幅、文字の折り返し、フォント・画像の読み込みによる変化も再計算する。スマホと通常の受験画面には位置合わせの余白を作らない。160px以上の余白には、上端寄りに余白の理由と本文へ進むボタンを表示する。新しい模試原稿では同じ属性で問題／解説の対応箇所を指定する。

サイトトップはGitHub mainの`dee8964`にある最新版と対応資産を使用し、「しくみを体験する」の次へ「実戦模試に挑戦する」カードを追加。Sites生成時はカードの模試リンクを同じSite内へ残す。表の列見出しは矢印の有無にかかわらず中央に配置する。通し受験から切り出した成績も時間条件を表示し、旧名の絞り込み条件は自動で引き継ぐ。

検証：`browser-reading.cjs`で44採点単位の左右対応、画像・本文高と画面幅変更、全大問のスマホ切替、早見表の除去、固定メニューの撤去、トップのカード順、見出しの中心座標、復帰先、個人成績不変、閲覧時の記録RPC 0件を確認。統計応答は模擬。


### 解説への集中と設問別の問題表示

作問方針・測定設計・開発用検証報告や問題から離れた一般論は、`trim_solution()`で画面と配布PDFから省く。正答の導き方・誤答肢の理由・必要な出典を残し、元原稿は保存する。解説PDFは32ページ。`validate_mock_exam_content.py`も同じ承認済み除去を適用して、残す本文と図表の一致・PDFの本文網羅を検証する。

`mark_problem_fragments()`で問題に`data-reading-for`を付与する。共通の文章・図表・プログラムと各採点単位の設問を明示し、対象の全解答欄が含まれるかビルド時に検証する。`ui/reading-problem.mjs`は先読み済みHTMLから必要な部分だけを取り出し、祖先構造とスタイルを保持してキャッシュする。先に該当設問が読めるよう、前方の共通資料は「共通の文章・図表を見る」で開ける形にまとめる。問題HTMLの再取得や再採点は行わず、正解変更・統計送信はできない。

問題画面の「解説に戻る」、ブラウザの戻る／進む、再読み込みに対応する。個人の受験履歴とは別に、履歴エントリーごとの表示位置をメモリーで保持し、ページを離れる際は既存のセッション状態にも保存する。狭い画面では印刷用のページ高さによる不要な空白を作らない。第3問の共通文章ア・イ、シ・ス・セは一つの「問題を見る」で同じ部分を開く。

検証は`browser-reading.cjs`（全44単位の抽出、5ボタン、余白案内、読み込みキャッシュ、ブラウザ履歴・再読み込み・スクロール復帰）と`browser-navigation.cjs`、`ui-revision.cjs`。PDFだけを更新する場合は`node scripts/build_mock_exam_pdfs.cjs solution`を使用できる。
